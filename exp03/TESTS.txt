D11 累加器口径：单元 + 端到端精确核对 + 注入必须被抓到
==============================================================================
  说明：初版的集成断言写成 `macc == 期望 or macc < 1000`，而后半句恒为真，
        整条断言是空的。独立复核用『只改 step 内实际强度为 min(mm+1,1000)、
        保留 move_mortality 单元测试不变』的注入证明了这一点。下面是补正。
  (i) 单元案例（初始 20 人 / 余数 0 / 强度 20 / 连续 10 次）：累计死 3、剩 17、余数 740 —— 期望 (3, 17, 740) ✓
      对照：按 N×初始size×强度 会得到 4 人，口径确实是按实际人数
  (ii) mm=49   原余数=0    size=20：
       出发 20（期望 20）| 死 0（期望 0）| 幸存 20（期望 20）| 余数 980（期望 980）
       人口账误差 0（期望 0）| 人口增量 0（期望 0） ✓
  (ii) mm=50   原余数=990  size=20：
       出发 20（期望 20）| 死 1（期望 1）| 幸存 19（期望 19）| 余数 990（期望 990）
       人口账误差 0（期望 0）| 人口增量 -1（期望 -1） ✓
  (ii) mm=100  原余数=0    size=20：
       出发 20（期望 20）| 死 2（期望 2）| 幸存 18（期望 18）| 余数 0（期望 0）
       人口账误差 0（期望 0）| 人口增量 -2（期望 -2） ✓
  (iii) mm=49 注入 min(mm+1,1000)：余数 0（健康期望 980）、幸存 19（健康期望 20） -> 被抓到 ✓
  (iii) mm=50 注入 min(mm+1,1000)：余数 10（健康期望 990）、幸存 18（健康期望 19） -> 被抓到 ✓
  (iii) mm=100 注入 min(mm+1,1000)：余数 20（健康期望 0）、幸存 18（健康期望 18） -> 被抓到 ✓
  (iii) 注：mm=1000 时 min(mm+1,1000) 与 mm 相同，该档位注入在原理上不可检出，未纳入本组。
  => D11 累加器口径（单元 + 端到端 + 注入检出） 通过
