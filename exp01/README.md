# exp01/ —— 验算脚本，不是引擎

**这不是文明引擎，也不是 EXP-01 的实现。** 这是一次性的验算脚本，用来检验
[`../docs/EXP-01-SPEC.md`](../docs/EXP-01-SPEC.md) 里的公式、单位、更新顺序与错误注入是否成立。
规格获批、目标语言定下来之后，本目录即可丢弃。

```
verify.py      规则的 Python 参考实现（全整数，无浮点进入状态）
run_tests.py   T1–T6 + 错误注入表
RESULTS.txt    上一次运行的完整输出（存档）
```

复现：

```bash
cd exp01 && python3 run_tests.py ; echo "exit=$?"
```

无依赖，Python 3.9+，整体约 4 秒。**必过项失败时退出码为 1**（已实测：故意让 T4 失败 → `exit=1`）。
种子集合 `[0, 12345, 777, 4242, 99, 31337, 2026]`，回归种子 0 在列。

## 它检验了什么

| 检验 | 判据 |
|---|---|
| T1 | 同种子两次运行逐位相同 |
| T2 | 第 150 年快照续跑至 300 年，与不中断运行逐位相同 |
| T3 | 抑制 A 区分裂后，B 区逐位不变**且** A 区确实改变 |
| T4 | 每 tick 整数守恒误差 == 0 |
| T5 | 迁移决策用的是过时信息（滞后 > 0 且存在事后看错） |
| T6 | 逆序遍历结果相同（长跑，采集与分裂都同时结算） |
| T7 | 两个群体争同一空位时，正序与逆序胜者相同且为 `min(band_id)`（定向场景） |

`state_hash` 覆盖 tick、每格 `stock/cap/regen`、每个群体的 `cell/size/store/bacc/dacc/mem/memt`、
以及全部 11 个账本计数。`region_hash` 覆盖同一套群体字段，但不含跨区块累加的全局计数。

错误注入版本全部是**同一份代码的开关**（`poison=` 参数），不是第二份实现。
组合注入用逗号，例如 `poison='seq,revorder'`。

## 它发现的三件事

1. **健康内核原本有顺序依赖。** 两个群体同格时，先被处理的从全量存量取份额。
   按 `band_id` 排序只让它可复现，没让它与顺序无关——顺序成了隐藏参数。
   已改为同时结算（各自算索取量，再按整数最大余数法逐格分配）。
2. **灭绝率恒为 0**（7 种子 × 300/1000 年）。这是宪法标记为可疑的信号，
   诊断见规格 §7.2 缺陷 1。**本轮明确不修**：不加最低人口清除阈值，不为了让灭绝出现而调机制。
3. **迁移的储存损失参数是死的**。`MOVE_LOSS_M = 0.150` 从未起作用，而且是结构性的：
   迁移只在 `E < 1` 时触发，`E < 1` ⟹ `store` 已被吃光。实测 807 个满足迁移条件的
   band-年样本里 `store` 全部为 0。见规格 §7.2 缺陷 5。**本轮不修，也不带进下一个切片。**

另外，分裂的冲突解决路径在长跑中**从不被执行**（175 次申请、0 次撞车），
所以它由定向场景 T7 单独覆盖——挂在长跑上的测试会永远是绿的。

## 不要拿它做什么

- 不要外推性能（0.04 秒/300 年只说明 64 格很便宜）
- 不要把 8 条 D 级参数当成标定过的值
- 不要把它的"人口曲线"当成任何关于真实历史的说法
