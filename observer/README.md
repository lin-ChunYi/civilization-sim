# OBS-01 文明观察台

一个**只读的观察与操作界面**：固定网页 + Python 后台 + 独立数据存储。
它调用已冻结的 EXP-03 引擎（`exp03/verify3.py` @ `6b6af4f`）跑模拟、记录逐年状态、在网页上回放。

**它不是一个新的世界机制。** 本轮没有扩大地图、没有接入 LLM、没有新增交易/战争/国家/宗教，
也没有改动任何人口或迁移公式。`exp01/`、`exp02/`、`exp03/` 三个冻结目录一个字节都没有动
（有测试盯着，见下面 O12）。

![地图](docs/screenshots/01-map.jpg)

## 本地怎么跑

**首次安装**（只做一次）：

```bash
cd /path/to/civilization-sim
python3 -m pip install -r observer/requirements.txt      # 只有 fastapi 和 uvicorn
```

**以后每次启动**（不需要再装东西）：

```bash
cd /path/to/civilization-sim
python3 -m uvicorn observer.app:app --host 127.0.0.1 --port 8765
```

然后在浏览器打开：**<http://127.0.0.1:8765>**

停止：在终端按 `Ctrl+C`。需要 Python 3.9+（开发与实测用的是 3.12.9）。

第一次打开时，页面里已经有一份**预生成案例**（`seed 4242 · SIGMA_M 400‰ · MOVE_MORT_M 50‰ ·
记忆臂 · 120 年`）。它是**预先真跑出来的**，随仓库分发，页面上带“预生成”标记——
它不是正在运行的任务，也不冒充实时计算。

## 页面上有什么

| 标签页 | 内容 |
|---|---|
| 世界地图 | 真实的 64 格地图（8×8、第 3/4 列不可通行、六邻接）。颜色深浅 = 资源存量，棕色圆点 = 群体（数字是人口）。同格多个群体排成一行分开摆放，互不遮挡，可分别点选。可切换“世界真实资源 / 选中群体的记忆”。 |
| 指标与曲线 | 总人口、群体数、野外资源存量、群体储粮、当年出生 / 原规则死亡 / 迁移死亡 / 迁移次数、当年缺粮÷需求，以及逐年表（当年值与累计值分列）。 |
| 群体与事件 | 当年的可核实事件 + 当年在世群体表。点群体看人口、储粮、位置、迁移轨迹、分裂来源。 |
| 运行记录 | 发起新的模拟；已完成的运行可重新打开回放，不必重算。 |
| 项目进度 | 前期研究 / EXP-01 / EXP-02 / EXP-03 / OBS-01 / EXP-04 / 后续能力的状态。 |

页面顶部始终显示：**当前运行、模型版本、实际参数、计算进度、正在回放的年份**。

时间轴区分两件事，不混为一谈：
**“已计算到第 N 年”**（后台算到哪了）与 **“正在回放第 M 年”**（你在看哪一年）。
播放、暂停、单步、调速、拖动年份、回到开局都只读取已保存的记录，**不会重算世界，也不会改写历史**。
改参数意味着**新建一次运行**，已有运行不会被修改。

地址栏支持定位与分享：`#tab=world&run=<运行号>&t=45&b=<群体id>&view=mem`。

## 数字的口径

- 资源、储粮、需求的原始单位是 **kcal**（整数账，不做浮点换算后再存）。页面同时显示
  **人年口粮**（1 人年 = 730,000 kcal = 2000 kcal/日 × 365），两个都标了单位。
- **当年值与累计值分开列**。当年出生 / 死亡 / 迁移死亡全部来自账本的**差值**
  （`cum[t] − cum[t−1]`），不用人口净变化冒充出生或死亡。
- 分母为 0 时显示**“不适用”**，不写成 0%（例如当年迁移 0 次时的误判率、第 0 年的缺粮率）。
- 64 位实体 id 一律以**字符串**下发，避免 JavaScript 的精度丢失；原始整数账保持精度，
  只在画图时按明确单位换算。
- 事件只有两个来源，页面上逐条标注：**模型自己的日志** `st['log']`（分裂、群体消失）与
  **状态差分**（`cell` 字段前后不同 ⇒ 迁移）。无法从年末快照还原的细节写**“未记录”**
  （例如某次迁移死了几个人——账本只记全局分项）。**不用 LLM 补编任何事件、动机或因果。**

## 记录层的纪律（这是本轮最关键的一条）

外部运行器的顺序是：**初始化世界 → 记录第 0 步 → 调用原 `step` → 记录状态副本与当步指标**。

记录层**只读取和复制状态**：不往模型对象里写任何观察字段，不消耗模型的随机数
（`adapter.py` 里一次都没有调用引擎的 `rng`），观察用的显示名与事件来源标注放在观察层自己的结构里。
验收测试 O1 用“开记录 / 不开记录”两次运行逐年比对 `state_hash`，并比对最终 `full_digest`。

## API

只读：`GET /api/health` `/api/config` `/api/milestones` `/api/map` `/api/runs`
`/api/runs/{id}` `/api/runs/{id}/series` `/api/runs/{id}/year/{t}`
`/api/runs/{id}/band/{band_id}[?at_year=N]` `/api/runs/{id}/relations[?at_year=N]`
写：`POST /api/runs`（新建并启动）`POST /api/runs/{id}/cancel` `DELETE /api/runs/{id}`
`POST /api/runs/{id}/continue`（从检查点续演，只接受 `additional_years` 与 `request_id`）

只读还有 `GET /api/runs/{id}/continuation`（这条记录此刻能不能续演；`supported` 是引擎能力、
`eligible` 是这条记录此刻的状态，两者不混用）。

取消是**有界**的：正常工作进程在当前这一年算完后自己停下；卡住的在协作窗口
（`OBSERVER_CANCEL_GRACE`，默认 15 秒）用完后被停止；进程身份查不到时**一个信号都不发**。
停止结果是**核实**出来的：只有确认那个进程不在了才写 `canceled`、才释放任务槽；
信号发了它还在、或者停没停下来查不到，都保持 `running` 并如实说明，下一轮再试。
只有用户明确按过取消才会走这条路 —— 没人取消时，算得慢的任务永远不会被动。
详见 [`../docs/OBS-01-API-CONTRACT.md`](../docs/OBS-01-API-CONTRACT.md) §6。

`at_year=N` 只读第 0..N 年已保存的记录 —— 回放到第 124 年时，档案里不会冒出第 125 年的迁移。
省略即全档案。字段与口径见 [`../docs/OBS-01-API-CONTRACT.md`](../docs/OBS-01-API-CONTRACT.md) §6，
实操交接见 [`../docs/OBS-01-HANDOFF-HISTORY.md`](../docs/OBS-01-HANDOFF-HISTORY.md)。

## 上限与访问保护

服务端校验所有输入（不只依赖前端控件）：种子 `[0, 2^31−1]`、年数 `[1, 300]`、
`SIGMA_M`/`MOVE_MORT_M` `[0, 1000]` 且必须是严格整数（`1.5`、`true` 都会被拒），
信息条件只能是 `memory` / `omniscient`。同时最多**一个**模拟任务在跑，重复启动返回 409；
运行条数上限 50、数据目录上限 512 MB、写请求每 IP 每分钟 12 次。

- **没设 `OBSERVER_TOKEN`**（本地默认）：读接口开放，**写操作只允许来自本机**。
- **设了 `OBSERVER_TOKEN`**：所有 `/api` 请求都必须带令牌，**服务端校验**。
  令牌由你在页面右上角填写，存在浏览器的 sessionStorage 里，**不写进前端代码，也不进版本库**。
  公网部署必须设置它。

页面不暴露 GitHub 凭证、服务器密钥，也没有任意文件读取能力：网页只能读到 `observer/web/`
下的静态文件和上面那几个 API。

## 在线部署（配置已准备，**尚未实际部署**）

本轮**没有真的上线**，只提供了配置。要上线还缺你的账号授权（以及付费实例的费用决定），
这两件事我不会替你做，也不需要你把密码或令牌贴进聊天。

**方式一：Render 蓝图（单服务）** —— 仓库根目录的 `render.yaml`。
在 Render 控制台用 “New → Blueprint” 连上这个 GitHub 仓库即可；`OBSERVER_TOKEN` 在控制台里填
（配置里写的是 `sync: false`，不落仓库）。依据官方文档（2026-09-11 核对）需要注意：

- **持久盘只有付费实例才有**。免费实例文件系统是临时的：重启或重新部署后，你自己发起的运行会消失，
  只剩仓库自带的预生成案例。要长期保存记录，就得用带 `disk` 的付费实例（配置里挂在 `/var/data`，
  并把 `OBSERVER_DATA_DIR` 指过去）。
- 挂盘的服务**不能多实例**，重新部署时**先停后起**（会短暂不可用）。本项目本来就是单实例、
  同时只跑一个任务，这个限制不影响使用。
- 构建阶段**访问不到**持久盘，所以不要在 `buildCommand` 里往数据目录写东西。

**方式二：Docker（任何支持容器 + 卷的平台）** —— `observer/deploy/Dockerfile`：

```bash
docker build -f observer/deploy/Dockerfile -t civ-observer .
docker run -p 8765:8765 -e OBSERVER_TOKEN=换成你的令牌 -v $PWD/observer-data:/var/data civ-observer
```

**两种更新要分清**：

| 变的是什么 | 怎么生效 |
|---|---|
| 功能与代码 | 推送到 GitHub → 平台重新部署（Render 蓝图里 `autoDeployTrigger: commit`） |
| 模拟继续推进 / 新增运行 | **只写数据目录**，网页轮询后自动读到，**不需要提交 GitHub，也不需要重新部署** |

浏览器回归页搬到了 `observer/tests/web/`（挂在 `/selftest`），注入脚本生成到同一处。
两边的接口、口径与前端测试钩子写在 [`../docs/OBS-01-API-CONTRACT.md`](../docs/OBS-01-API-CONTRACT.md)，

## EXP-06 接入（obs-1.4，新增字段全部向后兼容）

`engine` 多一个取值 `exp06`（援助记忆与优先回助），`POST /api/runs` 多一个**可选**参数 `recip_m`。
`engine=exp06` 的运行多三样东西：`aid` 事件带 `phase`（是否走优先阶段）与 `repay`（供给方记得对方帮过自己）；
群体记录带 `aid_memory`（谁以前帮过我、累计多少、最近哪一年，**只由实际转移累加**）；
年份记录多 `recip` 段（含 `changed` = 优先规则**真的改变了分配**的次数）。

> 回助 · 群体-A 向 群体-B 援助了 …（优先回助阶段：供给方记得对方帮过自己）

**`repay` 与 `changed` 必须分开显示**：`RECIP_M=0` 时 `repay` 照样出现（碰巧），
只有 `changed` 能说明规则真的起了作用。其它引擎的记录完全不变。

## EXP-05 接入（obs-1.3，新增字段全部向后兼容）

`engine` 多一个取值 `exp05`（同格食物援助），`POST /api/runs` 多一个**可选**参数 `aid_m`。
`engine=exp05` 的年份记录多一个 `aid` 段（当年活动次数 / 逐笔转移 / 数量 / 供给方 / 接收方 /
预算 / 缺口 + 累计），事件列表多 `type:"aid"` 的条目：

> 群体-7B4694 向 群体-90C5CA 援助了 3323254 kcal（4.55 人年口粮），地点在第 10 号格

即**第 X 年、哪一格、谁给谁、多少食物**，两种单位都给了。
**`events`（一次多人援助活动）与 `transfers`（一笔转移）是两个计数，不要混用。**
exp03/exp04 的记录完全不变，前端必须容忍缺席。字段见
[`../docs/OBS-01-API-CONTRACT.md`](../docs/OBS-01-API-CONTRACT.md) §2、§6。

## EXP-04 接入（obs-1.2，新增字段全部向后兼容）

观察台现在能跑两个引擎：`exp03`（冻结基线）与 `exp04`（同格信息交换）。
`POST /api/runs` 多两个**可选**参数 `engine`、`share_m`；不传等于老行为。
`engine=exp04` 的年份记录会多一个 `share` 段（当年的交换组次 / 参与人次 / 收到 / 采纳 /
拒绝 / 决策改变数 + 累计采纳），事件列表会多 `type:"share"` 的条目：

> 群体-97AC8E 把第 6 号格的记忆（63510000 kcal，记于第 43 年）传给了 群体-6876D3，地点在第 14 号格

即**哪一年、哪一格、谁传给谁、传的是哪个格的记忆、值多少、那条记忆原本记于哪一年**。
时戳照抄来源不刷新；每条都能在交换前快照里找到同源。`exp03` 的记录完全不变、没有这两样，
前端必须容忍缺席。字段定义见 [`../docs/OBS-01-API-CONTRACT.md`](../docs/OBS-01-API-CONTRACT.md) §2、§6。

## 第三轮：后台可靠性（任务槽回收 / 状态转换表 / meta 原子性）

| 原来的毛病 | 现在的做法 | 盯着它的检查 |
|---|---|---|
| 工作进程被 kill 或根本没起来，记录停在 `running`/`queued`，把唯一的任务槽**永久占死**，只能重启服务才能再跑 | `reap_stale()`：`running` 但 pid 不是这次运行的活工作进程 → 回收；`queued` 且 pid 已不在、或超过 `QUEUE_GRACE_SEC`（默认 20 秒）仍无人接手 → 回收。活着的进程一律不动。回收即 `interrupted`（终态），已算年份仍可回放。`POST /api/runs` 与 `GET /api/runs` 都会先回收 | O19a–h |
| 状态转换没有明面上的规矩，靠各处 SQL 条件散着守 | 一张 `TRANSITIONS` 表：**终态 done/failed/canceled/interrupted 不再变**；生产路径一律走 `transition()`，`force_status()` 只给测试构造前提用 | O20a–e |
| `meta.json` 写到一半会把 `GET /api/runs/{id}` 打成 500 | 写：临时文件 + `os.replace`（原子）；读：损坏或残缺一律返回 `null`，接口照常 200，前端按契约自动补取 | O21a–d |
| 取消一个进程已经不在的运行，只是设了标志位，没人会读 | 发现进程不在就直接回收任务槽并标中断 | O19 一并覆盖 |
| 重启恢复不看停止结果，`unknown`/`alive` 照样 `transition` 成 `interrupted` 并释放任务槽；返回数与启动日志还把没收尾的也算成"已标记为中断" | 只有确认 `gone` 才写 `interrupted`、才放槽；`alive`/`unknown` 保持活动状态并写 `recovery_note`，返回数只计真正转成中断的。收尾写入带 `allow_from`/`expect_pid`，并发 `done` 与 pid 更换都不被覆盖。之后只靠 `reap_stale()` 重新探测（不发信号）收尾 | O32a–i |
| `stop_worker` 把"查不到"当成"停下来了"（`_is_our_worker` 对 gone 和 unknown 都返回 False），SIGKILL 失败也无条件返回成功；`enforce_cancels` 又完全忽略返回值，照样写 `canceled` 并释放任务槽 —— 旧工作进程还活着、还在往 `years.jsonl` 里**追加**（数据库围栏管不住文件写入），新运行却已经起来了 | `stop_worker` 改为返回 **gone / alive / unknown** 三态，SIGTERM 与 SIGKILL 之后都要**核实**；**只有确认 gone 才写 `canceled`、才放槽**，alive/unknown 一律保持 `running`、保留取消请求、写明"任务槽先不释放"。每次发信号前重新核验身份，升级到 SIGKILL 之前再确认一次（pid 可能刚被复用）。`recover_interrupted` 同样不把 unknown 说成"已被停止" | O31a–o |
| 取消只设标志、工作进程在**年边界**才读；进程活着却卡在某一步时那个标志永远读不到，唯一的任务槽再也放不出来，只能重启服务 | `enforce_cancels()`：确认是本次运行的活进程 → 先给 `CANCEL_GRACE_SEC`（默认 15 秒）协作窗口让它自己停，窗口用完还在才 SIGTERM → SIGKILL；确认已不在 → 直接判 `canceled`；**身份查不到 → 一个信号都不发**，只记一句人话，下一轮再看。收尾写入带 `allow_from`/`expect_pid`，抢先写完 `done` 的赢家不被覆盖。**判据只有"用户按过取消"这一条**，没有任何"多久没进度就停掉它"的规则 | O30a–u |
| 进程探测失败（`ps` 超时、权限不足、系统调用出错）被当成“进程死了”，会误回收一个还在跑的任务 | 探测改成三态 **alive / gone / unknown**；**未知一律不回收**，宁可让槽多占一会儿。`pid` 被别的进程复用判为 gone，不误认为活着 | O23a–d |
| 回收的写入不核对检查时看到的状态与 pid，可能把“检查之后刚启动”的任务停掉 | 回收写入带 `allow_from=[检查时的状态]` 与 `expect_pid=检查时的 pid`；中间变了就落空，本轮不回收，下一轮再看 | O23e |

注入验证（不会红的检验等于没有检验）：去掉 `app.py` 里的回收调用 → O19g 红；
去掉转换表的 SQL 守卫 → O20a/b/e 红；`read_meta` 退回不容错 → 直接抛 `JSONDecodeError`（即接口 500）。

## 第二轮审阅修掉的四件事

| # | 原来的毛病 | 现在的做法 | 盯着它的检查 |
|---|---|---|---|

## 已知限制（不要当成已解决）

1. **一次运行被打断之后，本身不会自动接着跑。** 但 EXP-06 的新建运行会在每个完整年度边界
   写检查点，可以显式**续演**：`POST /api/runs/{id}/continue` 会新建一条子运行，
   先原样复制父运行的历史前缀，再从检查点接着算。口径、原因码与限制见
   [`../docs/OBS-CONTINUATION-CONTRACT.md`](../docs/OBS-CONTINUATION-CONTRACT.md)。
   只有 EXP-06 写检查点；旧运行与预生成案例没有检查点，因此没有续演资格，也不自动补跑。
   累计世界年上限 3000，**实测到 600 年**。
1b. **服务重启不做跨进程续跑。** 服务重启时，先**停掉**可能还活着的旧工作进程（SIGTERM，必要时 SIGKILL），
   **核实它确实不在了**，再把这条任务标为**“中断”**；工作进程那边所有数据库写入都带围栏，
   所以标成中断之后谁也改不回 `done`。已完整保存的年份仍可回放，继续推进请新建运行。
   停不下来、或者停没停下来查不到时，记录**保持活动状态、任务槽继续占着**，
   并写一条 `recovery_note` 说明 —— 旧进程还可能往 `years.jsonl` 里追加年份，
   数据库围栏管不住文件写入，所以"文案承认没停下来"是不够的。之后不再主动发信号：
   每次查看运行列表都会重新探测，确认它不在了才收尾；想主动结束它请按取消。
   不假装实现了存档兼容或自动恢复。
2. 同时只跑**一个**模拟任务。已有**活着的**任务在跑时启动新任务会明确报 409，不排队、不无限起后台进程；
   占槽的进程若已经不在，任务槽会被自动回收，不需要重启服务。
   卡死的工作进程**通常**能靠取消放出槽：用户按取消后，协作窗口用完会停掉**已核验身份**的
   那个进程（见上表）。但"有界"指的是**升级动作**有界，不是"槽一定在 N 秒内放出来"——
   连 SIGKILL 都杀不掉的进程会让这条运行一直停在 `running`，接口如实这么说，不假装它结束了。**仍然没有心跳**：没人按取消时，一个卡死的任务会一直占着槽 ——
   这是刻意的，"暂时没进度"不是停掉一个正常计算的理由，宁可让人来判断。
3. 页面只显示**本服务自己的数据库**。它看不到、也不假装能看到别处（例如另一台电脑上）的任务。
4. 逐年记录是**全量快照**（每年一份 64 格存量 + 全部群体 + 记忆），120 年约 390 KB；
   300 年约 1 MB。上限靠年数、运行条数、数据目录大小三道闸控制。
5. 群体层的出生 / 原规则死亡 / 迁移死亡**分不开**——账本只记全局分项，页面如实显示“未记录”。
6. 模型自身的既有口径照原样显示，不替它修正：群体**自己所在格**的存量每年刷新，但时间戳只在
   侦察或迁入时更新，所以记忆视图里本格可能显示成“若干年前”。
7. 继承 EXP-01/02/03 的全部已知限制：迁移储存损失结构性恒为零、默认样本无灭绝、
   多数假设是 D 级、跨版本存档兼容与人口学标定**都没有做过**。
