## 1. 只加一个机制

同一格内，有余粮的群体可以把一部分食物援助给当年缺粮的群体。

> **这是一条明确设定的援助规则，不是涌现。** 本切片**不宣称**已经出现合作、道德或制度：
> 谁能给、给多少、给谁，全部由下面写死的公式决定。

唯一的新参数是 `AID_M ∈ [0,1000]`（严格整数）：**供给方愿意拿出多少比例的可援助余粮**，
**不是参与概率**。0 关闭援助；1000 愿意拿出全部可援助余粮；**没被接收的仍归供给方**。

## 2. 相位与公式

位置：**采集结算（相位 2）之后、消费（相位 3）之前**。

| 量 | 定义 |
|---|---|
| 可用粮食 | `avail = 当年采集 + 原有储粮` |
| 当年需求 | `need = 人口 × NEED_PC`（730,000 kcal/人年） |
| 供给方 | `avail > need`，先保留自己的 `need`，预算 `budget = (avail − need) × AID_M / 1000`（向下取整） |
| 接收方 | `avail < need`，缺口 `gap = need − avail`，**最多补齐 gap** |

`size == 0` 的群体不参与（当年没有需求，且马上会被移除）。

**本切片的假设**（写明，不含糊）：同格群体能**如实**提出缺粮请求。
不跨格送粮，不增加运输、欺骗、信任、债务或交换回报。

## 3. 结算规则（统一匹配、统一结算）

同一格内，全部按**同一份援助前状态**计算：

1. `S = Σ budget`（供给合计），`D = Σ gap`（缺口合计），实际转移总量 `T = min(S, D)`。
2. **接收方分配**：`S ≥ D` 时各自补满缺口；否则按 `gap` 比例用**最大余数法**摊分 `T`
   （余数按"余数降序、`band_id` 升序"派发——与 EXP-01 的采集分配同一套规则，不另发明）。
3. **供给方分配**：`S ≤ D` 时各自付出全部预算；否则按 `budget` 比例用同一套最大余数法摊分 `T`。
4. **配对**：双方都按 `band_id` 升序做瀑布式匹配，逐笔生成 `(供给方, 接收方, 数量)`。

因此结果**与群体遍历顺序无关**；接收方也**不能**在本相位内把刚收到的粮再转赠出去
（它的预算按援助前状态算，是 0）。

**记账**：每笔转移都记 `(tick, 格, 供给方, 接收方, 数量 kcal)`。
供给方减少多少、接收方就增加多少（同一个 `amt`），不重复扣收获或储粮；
援助相位本身**不增加全图食物、不直接改变人口**——它只改变当年 `avail` 在同格群体之间的分配。

**两个计数不能混**：`aid_events` = 发生过援助的"格 × 年"活动次数（一次多人援助算 1）；
`aid_transfers` = 逐笔转移的笔数。

### 5.1 正确性（完整输出见 `exp05/TESTS.txt`）

- **F3 `AID_M=0` 逐步退化恒等**：对 EXP-04 @`68015cc` 逐 tick 全同（用 EXP-04 自己的哈希），
  再关掉 `SHARE_M` 则逐 tick 复现 EXP-03。
- **F5 定向场景逐笔精确核对**：7 个场景（供给充足 / 供给不足 / 整数余量 / 预算比例 /
  无供给方 / 无接收方 / 多人竞争）全部与**独立重算**的分配逐笔相同，总量与活动数也对得上。
- **F1 三本账每 tick 恒为 0**：能量守恒、人口恒等、援助账（逐笔合计 == 账上总量）。
- **注入必须真的会红**：`aidfab`（凭空生粮）被守恒账抓到；`aidcross`（跨格）被同格检查抓到；
  `aidoverbudget`、`aidregift`、`aidseq` 要在**供给 < 需求**的定向场景才承重；
  `aidovergap` 要在**供给 > 需求**的场景才承重。
- **长跑里这几条路径基本不被走到**：200 年里只有 17 笔援助，其中"供不应求"只出现 5 个 tick。
  这与 EXP-01「分裂冲突 175 次申请撞车 0 次」是同一课——所以它们挂在定向场景上，不挂长跑。

**能说的（原始描述）**：

- 援助**确实在发生**，而且能覆盖参与格里 20%–61% 的当年缺口。
- **末人口与累计人年随 `AID_M` 上升而下降**（`SIGMA=0`：3620 → 3418 → 2881），
  缺粮强度在 `AID_M=1000` 时也略差。逐种子配对看（§4 表），方向并不一致：
  `SIGMA=400 seed=31337` 是 392 → 345 → **577**，`seed=777` 是 168 → 230 → 183。
- 因此：**"援助一定增加长期人口"在本配置下没有被数据支持**，这一条按事先约定**不设为必过结论**，
  也不调参、不制造灾荒去把它做出来。

**不能说的**：

- 不能说"援助有害"。本轮**没有分离**两件事：援助本身的直接效果，与它触发的连锁
  （谁活下来、谁因此留在原地或迁走）。要分离需要专门的定向实验，本轮**没有做**。
- 没有预注册的检验统计量、没有空对照、没有噪声地板，**不做趋势推断**。
- 援助总量相对全局需求很小（几百人年口粮 vs 几十万人年），读数差异里有多少来自援助本身，
  本轮无法回答。

## 6. 读数须知与限制

1. 援助在自然运行里**稀少**（同格并存只在 6%–10% 的 tick 出现），所以结算规则的正确性
   由定向场景负责，长跑只负责观察。
2. `aid_events`（活动）与 `aid_transfers`（笔数）是两个计数，不要相加也不要互相替代。
3. 覆盖率只统计发生过援助的格，不是全局缺粮率。
4. 继承 EXP-01～04 的全部已知限制：迁移储存损失结构性恒为零、默认样本无灭绝、
   多数假设为 D 级、跨版本存档兼容与人口学标定都没有做过。
