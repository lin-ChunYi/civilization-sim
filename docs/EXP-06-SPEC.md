## 1. 规则（三条本轮定死的模型假设，不冒充现实历史定律）

**援助记忆**：每个群体记 `band['amem'][援助过我的群体] = [累计 kcal, 最近年份]`。
**只由实际转移累加**；不读第三方的全知关系表，不生成好感度。
**记忆不是债务**：不要求等额偿还，不自动结盟，除"优先顺序"外不影响任何规则。

**优先回助**：新参数 `RECIP_M ∈ [0,1000]`（严格整数）——供给方把预算的 `RECIP_M/1000`
**优先**分给"过去帮过我、现在又缺粮"的同格群体。EXP-05 的供给预算、同格限制、
接收缺口上限**全部保持不变**。没有历史关系也照常援助（开局不会出现"所有人都不帮忙"）。

**关系存续**：
- **分裂的子群体不继承记忆**——它没有实际接受过任何援助；父群体的记忆原样保留。
  （被否掉的做法：子群体复制父群体的记忆——那会让一次实际援助在多个群体的记忆里重复计数，账也对不上。）
- **群体消失时**，它自己的记忆随之丢失，数量记入 `amem_dropped_kcal`，所以记忆账仍然闭合；
  **别人对它的记忆保留**（它确实帮过别人，只是再也无法回助），由 `amem_dangling` 可观察。
- 完整历史永远留在 `aid_log`，**一次实际援助只记一次**。

## 2. 结算（优先阶段与普通阶段统一核算）

同一格内，全部按**同一份援助前状态**与**本年援助之前的关系快照**计算：

1. **优先阶段**：`pbudget_d = budget_d × RECIP_M/1000`。目标 = 该格中缺粮、且出现在
   `amem_pre[d]` 里的群体；权重 = 记得对方帮过自己的累计量；用**最大余数法**摊分
   `min(pbudget_d, Σ 目标缺口)`，每个目标先按自己的缺口封顶。
   各供给方**独立提议**；同一接收方被多家提议且合计超过它的缺口时，**按提议额比例统一裁减**
   （独立提议 → 统一裁决 → 一次提交，与 EXP-01 的采集冲突解决同一套idiom）。
2. **普通阶段**：优先阶段**没用掉的预算**连同其余预算、连同剩余缺口，跑 EXP-05 原规则
   （`T = min(ΣS, ΣD)`，两侧最大余数法，`band_id` 升序瀑布式配对）。
3. 两阶段合计：**每个供给方 ≤ 自己的预算，每个接收方 ≤ 自己的缺口，不重复送粮**。
4. **结算完才更新记忆**：接收方把这次实际收到的量累加进 `amem`。
   因此**同一轮送粮不可能立刻制造回助资格**（G8 直接验证）。

**排序与整数**：优先目标按 `band_id` 升序、权重按记忆累计量；一切摊分都用最大余数法
（余数降序、`band_id` 升序），与既有规则保持同一套，不另发明。

## 3. 怎么区分"碰巧帮了旧伙伴"和"优先规则改变了分配"

- **回助（repay）**：供给方记得对方帮过自己的那些转移。**`RECIP_M=0` 时它照样发生**——那是碰巧。
- **分配改变（recip_changed）**：同一份援助前状态下，把 `RECIP_M` 换成 0 **再算一遍**，
  两次**逐对群体的总额**不同的"格 × 年"次数。这才是"优先规则真的改变了分配"的直接计数。

  > **判据已修正（本批）**：最初比的是逐笔转移列表，于是"同一对群体、同样总额、只是被拆成
  > 优先 + 普通两笔"也被算成了改变——那只是记账分阶段，谁拿到多少一点没变。
  > 现在比的是逐对总额，计数相应下降（`SIGMA=0 RECIP=1000`：118 → 47），
  > 这组才是诚实的数字。对照明细（开/关两种分配）也一并对外提供。
  它是**只读诊断**，不参与规则（`poison-recipdiag` 证明它一旦回灌就会被抓到）。

### 4.1 正确性（完整输出见 `exp06/TESTS.txt`）

- **G3 `RECIP_M=0` 逐步退化恒等**：对 EXP-05 @`d20a015` 逐 tick 全同（用 EXP-05 自己的哈希，
  它不认识 `amem`，所以"新增的记忆状态"不会被误判成演化偏差）；再关掉 `AID_M` 则复现 EXP-04。
- **G5 端到端精确核对**：7 个定向场景与**写在测试文件里的独立参考实现**逐笔相同
  （参考实现不能和被测实现同住一个文件——EXP-05 那轮就在这里栽过一次）。
- **G1 四本账每 tick 恒为 0**：能量守恒、人口恒等、援助账、**记忆账**
  （在世记忆 + 随消失丢失 == 实际援助总量）。
- **G9b 定向场景**：自然运行里"带记忆的群体消失"一次都没发生（扫描里 dropped/dangling 恒为 0），
  所以用迁移死亡强度拉满的场景专门验证：自己的记忆记账丢失、别人对它的记忆保留。
- 六个注入 `recipseq / recipover / recipbudget / recipfab / recipsame / recipdiag` 全部实测会红；
  其中 `recipbudget`、`recipover`、`recipdiag` 必须挂在**构造场景**上才承重。

|---|---|---|---|---|
| 0 | 0 | 0.790% | 2881 | 565240 |

**能说的（原始描述）**：

- **机制确实在起作用**：优先阶段有 88–223 笔转移，**真·分配改变 29–47 次**（`RECIP_M=0` 时恒为 0）。
  "过去的援助影响了后来的分配"这件事**被直接计数证明了**，不是靠日志多记一份。
- **回助不等于优先规则起作用**：`RECIP_M=0` 时也有 93–189 笔回助（供给方碰巧就是旧伙伴）。
- **但聚合结果没有明显改善**：缺粮强度 0.790% → 0.791% → 0.803%，末人口 2881 → 2908 → 2844；
  逐种子看（`SCAN.txt` §5），`777`、`2026` 等几个种子三档**完全一样**，
  尽管这些运行里分配确实被改变过。
- **没有出现"关系网"**：重复往来（双向都援助过的群体对）54 → 48 → 52，并没有随 `RECIP_M` 增加。

**不能说的**：

- **不宣称出现了互惠规范、联盟或道德。** 记忆与优先顺序都是写死的规则。
- 不把"优先回助带来改善"设成结论——本样本没有支持它，如实保留，**不调参、不强造关系**。
- 没有预注册的检验统计量、没有空对照、没有噪声地板，**不做趋势推断**。
- 援助本身在自然运行里就稀少（EXP-05 已量），优先回助是在稀少事件上再加一层条件，样本更小。

## 5. 读数须知与限制

1. `repay`（回助）与 `recip_changed`（分配改变）是**两个不同的计数**，不能互相替代。
2. 记忆的三条存续规则是本轮假设，**不是现实历史定律**；"子群体不继承"这一条尤其是可争议的选择，
   已记入待办备查。
3. 扫描里 `amem_dropped` / `amem_dangling` 恒为 0，说明那两条路径**自然运行没有覆盖到**，
   只由 G9b 的构造场景覆盖。
4. 继承 EXP-01～05 的全部已知限制。
