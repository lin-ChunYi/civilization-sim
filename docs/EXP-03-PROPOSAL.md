# EXP-03 方案（待批准，批准前不实现）

**基线**：EXP-01 @ `20da486`、EXP-02 @ `c5a1f18`，均冻结只读。
**范围**：**只加一个机制**。不扩大地图、不接 LLM、不加社会机制、不重开领域研究、不改既有机制的参数。

---

## 一、新增的那一个机制

**迁移的代价作用于人口，而不是储存。**

```
群体每完成一次迁移：
    macc += size × MOVE_MORT_M          # 与出生/死亡同一套整数累加器idiom
    lost  = macc // 1000 ;  macc -= lost × 1000
    size -= lost                         # 储存不变，随幸存者一起走

新参数只有一个：MOVE_MORT_M ∈ [0, 1000]（千分之一）。
MOVE_MORT_M = 0 时该项退化为恒等。
```

用累加器而不是 `size × MOVE_MORT_M // 1000` 直接取整，是因为后者有量化死区：在 2% 的档位上，小于 50 人的群体每次迁移都损失 0 人——而本世界的群体典型规模就是 20–30 人，机制会对多数群体完全失效。累加器沿用既有 `bacc`/`dacc` 的写法，不引入新机械。

现有的 `MOVE_LOSS_M`（作用于储存）**保持原样不动**，它结构性恒为零这条限制也照旧记录。本机制是另加一条代价通道，不是去修它。

## 二、它要回答什么问题

**在这个世界里，决策到底能不能产生后果？**

EXP-01 与 EXP-02 合起来给出的是一幅一致的测量图景：**决策通道接近惰性**。

- 信息滞后 4.5 年，但事后看错的迁移只有约 1.5%；
- 全知对照臂与记忆臂在福利指标（累计缺粮、人口、群体数）上互有高低，**没有稳定方向**；
- 迁移目前没有代价（`MOVE_LOSS_M` 结构性恒为零）；
- 加入资源波动之后，误判率**没有**上升（B1 未被支持）。

也就是说：到目前为止，选得好和选得坏几乎是同一回事。**在这种情况下继续往上加社会机制（胁迫、交换、义务），每一个都会在"决策几乎不产生后果"的世界里被验收**——我们会得到一串"机制工作正常"的结论，而它们其实都没被真正检验过。

迁移死亡率是让"选错"第一次真正付出代价的最小改动：它只动一条已有动作的结算，不引入新的实体、关系或社会结构。

**为什么不是"储存被他人取走"**：那仍然是通往制度的那条路，但它是一个**群体间**机制，会同时引入新的关系边与新的决策类型。在决策后果性还没被确认之前引入它，等于在一个不可判读的底座上加两层。它继续留给后面。

## 三、与已有基线的对照方式

两条退化恒等式，构成一条链：

| 条件 | 必须复现 | 判定口径 |
|---|---|---|
| `MOVE_MORT_M = 0` 且 `SIGMA_M = 0` | **EXP-01 基线** | 用 `exp01/verify.py` 自己的 `state_hash`，**逐步**比对 300 tick |
| `MOVE_MORT_M = 0` 且 `SIGMA_M = s`（每个档位） | **EXP-02 基线** | 用 `exp02/verify2.py` 自己的 `state_hash`，**逐步**比对 300 tick |

两份基线都按路径只读加载，**不修改**任何一份。`run_id` 与两份基线都必须不同（新参数进了参数指纹，这是正确行为）——每条恒等式都同时断言"状态相同"与"身份不同"。

主对照仍是**配对比较**：每个 seed × 每个 `(SIGMA_M, MOVE_MORT_M)` 组合，同时跑记忆臂与全知对照臂。

**扫描网格（刻意压小）**：`SIGMA_M ∈ {0, 400}` × `MOVE_MORT_M ∈ {0, 20, 50, 100}` × 7 个种子 × 2 臂 = 112 次运行。`SIGMA` 只取两档是为了不把一个机制的实验变成两个机制的交叉实验。

## 四、正确性验收标准

**必过（二值，与现象无关；任一失败 ⇒ 退出码非零）**

| # | 判据 |
|---|---|
| D1 | 每 tick 整数守恒误差 == 0，全部组合。迁移死亡**不消耗能量**：储存随幸存者保留，人不是能量，因此守恒式不变——这一条要显式验证而不是假定 |
| D2 | 同种子同组合两次运行逐位相同 |
| D3 | 第 150 年快照续跑至 300 年，与不中断运行逐位相同 |
| D4 | 新增字段（`macc`、`MOVE_MORT_M`、迁移死亡累计）确实进了 `state_hash`：逐字段改一位，哈希必须变 |
| D5 | 群体遍历逆序不变 |
| D6 | 资源格遍历逆序不变 |
| D7 | **双重逐步退化恒等**（见上表两行），且 `run_id` 与两份基线都不同 |
| D8 | 区块隔离（保留；不强求它发现未被触发的错误） |
| D9 | `MOVE_MORT_M` 校验：先查严格整数类型（排除 bool），再查 `[0,1000]` 范围；补非法类型、越界值、合法边界（`0/1/999/1000`）回归，合法值跑 3 tick 后状态全为整数 |
| D10 | 错误注入 `poison-mort-seq`：迁移死亡的累加改成按调用序推进的全局量而非每群体独立 ⇒ **必须打破 D5**（群体遍历逆序不变）。在明确构造的场景里验证，不挂在长跑上 |
| D11 | 定向场景：一个群体连续迁移 N 次，累计损失必须等于 `floor(N × size × MOVE_MORT_M / 1000)` 的累加器口径值——即**量化死区确实被消除**，而不是靠"跑久了平均下来差不多" |

C9 那类**有场景前提的检查，前提必须由构造保证**；找不到满足前提的位置时报缺，不计通过也不计失败。**无迁移时相关比率记"不可计算(分母0)"，不记 0%。**

**观察（不判定通过与否）**

| # | 观察 |
|---|---|
| O1 | 每个 seed × 每个组合，记忆臂与全知臂的：迁移次数、误判分子/分母、累计缺粮、人口、群体数、累计迁移死亡 |
| O2 | 资源账（名义/计划/入账/被容量挡）——沿用 EXP-02 的口径，防止把资源变化误读成决策效应 |
| O3 | **待检验假说 H1**：全知臂相对记忆臂的福利优势（以累计缺粮与末期人口衡量）随 `MOVE_MORT_M` 上升。**只预注册方向，不预注册数值。** |

**H1 不成立就照实报告"本配置与本样本未支持"**，不调参追曲线，也不就此宣布找到了另一个原因——与 EXP-02 的 B1 同一处置。若 H1 也不成立，那是一个比 B1 更重要的否定结果：它会说明**在这套规则下决策后果性可能根本建立不起来**，而那应当改变后续路线，不是改参数。

## 五、明确不做
