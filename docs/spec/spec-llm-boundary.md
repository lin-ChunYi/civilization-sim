## 1. 纲领第 5 条的机械重写与 LLM 权限矩阵

### 1.1 原文与它为什么不可判定

纲领第 5 条原文：

> **规则与 AI 分离**：AI 可以负责人物和组织的判断、计划、解释、文化创造等难以公式化的部分，但 AI 不能直接决定客观结果。例如 AI 可以决定发动战争，但战争胜负必须由世界模拟规则根据军力、经济、后勤、地形、士气、技术、将领能力和随机因素等计算。

四处不可判定，逐条给出红队出处：

| 缺陷 | 说明 | 出处 |
|---|---|---|
| "客观结果"没有外延 | `战争爆发` 本身就是一个客观结果。第 5 条只保护 `P(结果∣事件发生)`，完全放弃 `P(事件发生)` | `llm-storytelling` §0 第一段、F1 |
| "直接"在代码里没有对应物 | 只要下游有任何一段代码把 LLM 产物解释成参数，AI 就已经在决定客观结果，而这条通道逃得过"AI 不能写世界状态"的检查 | `mandate-contradictions` F3 |
| "解释"是因果链的写入权 | 交出去等于第 2 条自动失效 | `llm-storytelling` F2 |
| "文化创造"是命名权与语义权 | 交出去等于"这个世界应该拥有自己的历史"自动失效 | `llm-storytelling` F3 |

### 1.2 第 5 条的机械可执行重写（规范文本）

> **5'（规则与 AI 分离，可执行形式）**
>
> **(a) 测度与转移归规则。** 世界状态的每一次转移，以及每一个进入采样的概率测度，其计算与写入都由内核纯函数完成。内核对 LLM 模块的编译期可见性为零（CI: `T-DEPGRAPH`）。
>
> **(b) LLM 的世界内输出恰有一种类型。** 在一个由规则创建的决策点 `s` 上，LLM 唯一被允许产出的、能影响世界的对象，是 `A(s)` 上的一个 `SimplexWeights`（§2.3 定义的整数权重向量）。任何其它输出（自由推理段、rationale、命名建议、解释、新动作请求）在类型上**无法**到达世界状态。
>
> **(c) 掷骰归我们的 PRNG。** 实际动作由 `spec-world-state` §6.7 的 Gumbel-max 从校准后的 `p_final` 采样，随机流为 `agent/llm_sampling`（该 spec §6.4 第 21 号流）。因此纲领第 6 条"记录随机种子"在 LLM 决策点上**字面成立**。
>
> **(d) 影响力被计价、被封顶、被公开。** 每次调用的操纵量 `D_KL(p_final‖π)` 记入 ledger；每世纪的总量有硬预算；越界只有两种处置（改 `π`，或强制按 `π` 采样）。
>
> **(e) 一切名字、标识符、命名空间归规则。** 见 §5。
>
> **(f) 一切自然语言归渲染域，且渲染域到世界的依赖是空的。** 见 §10、§11。
>
> **(g) 存在一个编译期配置，使 (b)(c)(d) 整体不存在，且世界仍能跑完三千年。** 见 §8.5、§12。

**这条重写否决了什么**（这是它相对原文的全部价值）：
- 否决了"AI 可以决定发动战争"的字面读法。AI 不能决定战争**是否发生**；规则的风险率 `λ(结构)` 决定"本 tick 是否出现一次开战机会"，只有掷中之后 LLM 才被唤醒（`llm-storytelling` F1 替代设计第 1 条）。
- 否决了"AI 负责解释"。解释权是因果图写入权，恒为零（§1.3）。
- 否决了"AI 负责文化创造"，降级为 **verbalization**（§5.6）。
- 否决了"LLM 输出一个选择"（X1）。

**关键行是最后一条，它是整张表里唯一"LLM 的意图能影响世界内内容"的地方，因此必须说清楚它的边界**：LLM 可以（经 Intent → Resolve）促成"某人宣布某人应向某人转移某物"这样一条命题被创造并传播。它**不能**决定这条命题长什么样以外的任何东西——它不能创造新的 `PropForm`，不能让 args 指向不存在的实体，不能给命题起名字，不能设置它的传播率、失真率、衰减率。

#### (iv) 汇总：唯一有意义的一行

"直接写全否"这句话本身**信息量为零**——它是任何架构都能宣称的。有意义的是下面这条，它是可静态判定的：

> **LLM 可间接影响的 L0 字段集合，恰等于 `⋃ writes_by(P1..P10)`，且这个并集在编译期可枚举。**

CI 测试 **T-WRITESET**：
```
llm_reachable = ⋃_{v ∈ PrimitiveVerb} PRIMITIVE_REGISTRY.writes_by(v)
kernel_fields = 全部 L0 字段
assert llm_reachable ⊆ kernel_fields \ FROZEN_FIELDS
assert 因果图字段 ∩ llm_reachable = ∅
assert 注册表字段 ∩ llm_reachable = ∅
打印 |llm_reachable| / |kernel_fields|   # 这是一个必须公布的数字
```
`|llm_reachable| / |kernel_fields|` 是"LLM 的世界影响面"的唯一诚实度量。它应当很小，且**只能减不能增**（每次增加都要走内核版本变更评审）。

### 这一节禁止了什么

- 禁止任何"LLM 可以决定 X 吗"的逐条辩论。判据变成机械的：X 是一个测度或一次状态写入 ⇒ 永远不能；X 是在规则给定的选择集上给出一个分布 ⇒ 可以。（`llm-storytelling` §2 表格第 5 行）
- 禁止 LLM 参与因果图的任何部分，包括"提出一条因果边"。它唯一合法的因果角色是**提出待消融检验的假设**，而写入因果图的是消融实测结果，不是它的话（`llm-storytelling` F2 第 3 条）。这条路径每个假设要付一次分叉重放，因此只能用于用户主动追问，不能常设。
- 禁止 LLM 读取任何 composite 标签、任何因果分析、任何近失账本、任何 `truth()`、任何绝对年份、任何绝对经纬度、任何真实地名。
- 禁止存在"LLM 请求分配一个 id / 一个名字 / 一个新命题形式"的 API。这些不是被拒绝的请求，是**不存在的句法位置**。
- 禁止用"AI 不能写世界状态"这一句话当作防线——它挡不住 `interpret_doctrine(text) -> Dict[str, float]`（`mandate-contradictions` F3："看到它就已经中了"）。真正的防线是 §6 的置换不变性检验加上"L0 里根本没有文本"。

## 2. Intent / 选择集 / 规则先验 π 的形式规格

### 2.1 决策点的生命周期（这一节的骨架）

```
tick t, phase 1 (env_slow) ──► 规则算出各类机会的年危险率 λ_c(结构状态)
tick t, phase 2 (sense)   ──► 为每个 Actor 构造 Perception（受限投影）
tick t, phase 2 末         ──► 对每个 (Actor, 机会类 c)：
                              CBRNG(stream=opportunity/c, ctr=(t, actor, slot, 0))
                              若未掷中 ⇒ 【不存在决策点】⇒ 无 Intent ⇒ 无 LLM 调用
                              若掷中   ⇒ 创建 DecisionSite s，枚举 A(s)，计算 π(·|s)
tick t, phase 3 (propose) ──► 调度器决定 s 是否 llm_eligible 且是否在配额内
                              是 ⇒ 异步发出调用（读**上一 tick** 的 View，见 §9.1）
                              否 ⇒ 直接 CBRNG 从 π 采样
tick t+1, phase 3          ──► 上一 tick 发出的调用结果回来：
                              解析 → SimplexWeights → 校准 → p_final
                              CBRNG(stream=agent/llm_sampling) Gumbel-max 采样得 a*
                              a* 与 rationale_hash 一起 commit 进 Intent 队列
tick t+1, phase 5 (material)─► Resolve(state, a*, rng) 纯函数裁决，写因果边
```

**"不存在决策点"这一步是整套设计的地基**（`llm-storytelling` F1 替代设计第 1 条）。它把 `事件基率 = 咨询频率 × p` 这条等式（该文 F1 的失败机制公式）从根上拆掉：咨询频率不再是工程预算的函数，而是 `λ_c(结构状态)` 的函数。

### 2.2 数据结构

```
// ─────────── 规则侧产出，LLM 只读 ───────────
DecisionSite {
  site_id        : H128            // = H128("site" || tick || actor_id || slot_id)
  slot_id        : u32             // PRIMITIVE_REGISTRY 中人工分配的常量（spec-world-state §6.4 末段）
  class_id       : u16             // 决策类（战争发起 / 制度提案 / 分裂 / 继承 / 迁移 / …）封闭注册表
  actor          : ActorRef        // Household | Person | RoleHolder
  tick           : Tick_y
  options        : [Option]        // 2 ≤ |A| ≤ 16（硬上限 64，见 L5）
  log_prior      : [LogQ32]        // log₂ π，定点；Σ 2^log_prior == 1<<32（int 精确，见下）
  noop_index     : u8              // A 中 NOOP 的下标；恒存在
  default_policy : PolicyId        // 非空，CI 强制（§8.5）
  llm_eligible   : bool
  view_ref       : ViewId          // 指向 phase-2 构造的粗化 View（§7.2）
}

Option {
  content_id : H128                // = H128(verb || canonical(args))；Gumbel 按它寻址
  verb       : PrimitiveVerb       // P1..P10 之一，或 NOOP
  args       : [Arg]               // Arg ::= EntityRef | Fixed(scale, i64) | Bucket(axis_id, u8)
  feasible   : bool                // 规则的可行性预检；不可行项不进 A
  reject     : Option<RejectCode>  // 若上一 tick 该动作被否决，回灌的结构化理由
}

// ─────────── LLM 侧产出，唯一能进世界的类型 ───────────
SimplexWeights {
  site_id : H128
  weights : [u16]                  // 与 options 等长；任意非负整数
}

// ─────────── 采样结果，进 Intent 队列 ───────────
ResolvedIntent {
  site_id        : H128
  chosen         : u8              // A 中的下标
  p_final_q32    : [Q32]           // 实际采样所用的分布（进 ledger 与因果账）
  source         : enum { LLM, PRIOR_FALLBACK, DEFAULT_POLICY }
  fallback_cause : Option<FallbackCode>
  rationale_hash : H256            // commit-before-resolve（见 §2.7）
  llm_call_id    : Option<H256>
}
```

**定点约束**（继承 `spec-world-state` D5，内核禁用浮点）：`log_prior` 与 `p_final_q32` 都是定点。`π` 的表示规范：内核算出的是**整数权重** `w_π: [u32]`，`π_i = w_π[i] / Σw_π`，且 `Σw_π` 固定为 `2^20`。这样 `π` 是精确有理数，`log₂π` 用查表 + 线性插值算到 Q32，`D_KL` 与 `H` 的计算全程定点、跨机器逐位相同。**这一条不是实现细节**：如果 `π` 是浮点，`D_KL` 就不可重现，整个 §3 的预算体系就不能进 CI。

### 2.3 `π` 的规范：下界、形状、来源

**(a) 下界（裁决 L5，［本文原创，无来源，D 级］）**

```
∀ i ∈ A :  w_π[i] ≥ 2^20 / 64        即  π_i ≥ 2⁻⁶
```

三个后果，缺一不可：

1. **每次调用的比特天花板是硬的**：`D_KL(p‖π) = Σ p_i log₂(p_i/π_i) ≤ log₂(1/π_min) = 6 bit`。没有这条，单次调用的操纵量无上界，§3 的预算就只是一个事后统计量而不是一个约束。
2. **`|A| ≤ 64`**（因为 `Σπ = 1`）。这同时是一条反"选择集膨胀"的约束：不能靠把选择集做大来稀释 `D_KL`。
3. **Gumbel-max abduction 良定**：没有零概率项，`provenance-replay-counterfactual` M8 第 3 步的精确后验可用。

**(b) 形状：`π(NOOP)` 必须压倒性大**

`llm-storytelling` F7 第 2 条："在没有结构性压力时，`π(不作为)` 应当压倒性地大。这不是保守，这是因为真实历史在记录层面绝大部分时间是无事的。"

规范：在 `|A| = 8` 且其余 7 项都取下界 `2⁻⁶` 时，`π(NOOP) = 1 − 7/64 = 0.891`。这是 `π(NOOP)` 的**上界**（下界由结构压力抬起来）。约束：

```
π(NOOP) ≥ 0.5   除非  pressure_index(s) > θ_press
```
`pressure_index` 只能由物理/经济/信息量构成（`llm-agent-social-simulation` M2 失效条件、AP7）。`θ_press` 标定见 §4.5。

**(c) 来源：`π` 必须被拟合，不能被撰写**

`llm-storytelling` F7 是整份红队里最难防的一条（"戏剧性没有被消灭，只是搬进了规则里，而且从此不可测"）。本规格照抄它的四条替代设计并加上可执行形式：

| 要求 | 可执行形式 |
|---|---|
| 有外部数据的量一律拟合 | `π` 的每个 logit 项必须在 `PRIMITIVE_REGISTRY` 里带 `justification_class ∈ {外部数据拟合, 理论推导, 量纲/守恒约束, 未校准, 叙事}`。**`叙事` 类的允许数量是 0**，CI 断言；`未校准` 的比例进首页 |
| 没有数据的量用最大熵先验 | `justification_class = 未校准` 的项，其先验形状**必须是该约束下的最大熵分布**，不得手写"我们觉得合理的值" |
| 参数-目标比 | `P/T`（自由参数数 / 有独立外部经验目标的校准目标数）必须出现在每份模型文档第一页；`P/T > 3` 即判"不可证伪"（`llm-storytelling` F7 可观察症状 1）。`spec-world-state` §3.1 已把 `free_param ≤ 15` 写进 CI |
| 禁止叙事节拍变量 | lint 黑名单：`years_since_last_*`、`dynasty_generation`、`peace_duration`、`crisis_cooldown`、`too_stable`。与 `spec-world-state` §2.4 的"目标导向调节器"行合并为一张表 |
| 调 `π` 的人与看叙事的人分离 | 治理条款，进 `spec-validation` |

**外部锚**（`llm-storytelling` F6 第 2 条）：Seshat Global History Databank 提供 49 个战争变量 / 17,536 条记录、3,439+ 条权力交接记录、357+ 条人祭记录、864 个政体（该红队自报为站点核验）。`λ_c` 与 `π` 在有对应变量的决策类上必须对它的**分布级**目标（前工业政体的战争起始率、政体存续时长分布、权力交接方式分布）拟合。**注意 `pseudo-simulation` S6 的警告**：Seshat 的编码约定足以翻转结论（Whitehouse et al. 2019 *Nature* 568:226–229 已因缺失值处理被撤稿，Retraction Notice *Nature* 595:320, 2021, DOI 10.1038/s41586-021-03656-3；Beheim et al. 2021 *Nature* 595:E29–E34, DOI 10.1038/s41586-021-03655-4，道德化神灵数据 61% 缺失）。因此拟合目标只能是**分布形状与关系**，不能是具体数值，且必须用三值逻辑（存在/不存在/未知）处理缺失。

### 2.4 Intent schema 的三条禁令

1. **不得含连续量。** 一切数值 args 是 `Bucket(axis_id, u8)` 或 `Fixed(scale, i64)`，且 `Fixed` 只允许出现在规则从结构状态算出、LLM 不能改的位置。理由：`llm-storytelling` F4 第三层证明 prompt 的数值精度控制着蝴蝶效应速率（"粮储 4.2 万石" vs "粮储 42,183 石"给出完全不同的反事实传播速度），而"这个格式多半是某人随手写的 `f"{x:.1f}"`"。把粒度提升为 schema 的一部分，就把它变成一个需要论证的设计决策。
2. **不得含绝对时间。** 无 `year`、无 `due_tick` 的绝对值——只有 `Bucket(delay_axis, k)`（"下个收成前 / 一到三年 / 一代人之内"）。理由同上，外加 `llm-storytelling` F8"纪年与时代标签即剧本"。
3. **不得含自由文本。** `Arg` 的类型定义里没有 `String` 这个 variant。这是类型级的，不是校验级的。

### 2.5 "不作为"的两层设计（裁决 L3，［本文原创，无来源，D 级］）

任务书要求"不作为必须是规则侧默认而非选项之一"；`llm-storytelling` F1 第 2 条要求"`不作为` 必须永远在集合里"。这两条只有分层才能同时成立：

| 层 | 含义 | 实现 | 谁决定 |
|---|---|---|---|
| **L0-noop**（机会不存在） | 这一年这个 Actor 在这一类事上**根本没有决策** | `λ_c` 未掷中 ⇒ 不创建 `DecisionSite` ⇒ 不调用 LLM ⇒ 不产生任何记录 | **纯规则** |
| **L1-noop**（机会出现但不采取） | 机会出现了，行动者选择不动 | `NOOP` ∈ `A(s)`，`π(NOOP)` 压倒性大 | 规则给先验，LLM 可以移动它，掷骰在我们 |

**L0-noop 在结构上不可被 LLM 触及**：它对应的是"没有发生的那 99.9% 的 tick"，而那些 tick 里连一次 API 调用都没有。这就是"不作为是规则侧默认"的准确含义。

**必测项 T-NOOP-BASE**：统计每个决策类的 `L0-noop 率`（未创建决策点的 Actor-年占比）与 `L1-noop 率`（创建了但选 NOOP 的占比）。两者都必须公布。若 `L0-noop 率` 随内核版本单调下降，说明有人在悄悄放宽 `λ`（`pseudo-simulation` F2 的"人手梯度下降"在本子系统的形态）。

### 2.6 被禁止的输出形态

| 形态 | 为什么禁 | 处置 |
|---|---|---|
| one-hot 权重（`weights` 只有一项非零） | 退化回 R1 的单点选择，反事实 abduction 与熵观测同时失效（`llm-storytelling` §2 三重损失） | 接受但记 `degenerate=true`；`degenerate_rate > 0.05` 即报警；ε-混合（§2.8）保证 `p_final` 仍非退化 |
| 全零权重 / 权重和为 0 | 无法归一化 | `PRIOR_FALLBACK` |
| 引用不存在的 option 下标 | — | `PRIOR_FALLBACK` |
| 自然语言的概率描述（"很可能""大概三成"） | 不可解析、不可定点化 | schema 层拒绝：用 `output_config.format` 的结构化输出（§9.4），不是自由文本解析 |
| 附带对 `A` 的修改建议 | 越权 | 忽略；若模型反复如此，走 `novel_action_request`（§2.9） |

### 2.7 归一化、校准、ε-混合（把 LLM 的自报概率变成可用的测度）

**四步，全部定点、全部可重放：**

```
1. 归一化到 1/64 网格（最大余数法，与 spec-world-state §2.5 的分配规则同一算法）
   raw    = SimplexWeights.weights            // [u16], 任意非负
   if Σraw == 0: → PRIOR_FALLBACK
   target = 64
   base_i = floor(raw_i * target / Σraw)
   r      = target - Σbase
   按 (raw_i*target mod Σraw) 降序、平局按 options[i].content_id 字典序升序，
   给前 r 项各 +1
   q_i    = base_i / 64                        // 精确有理数，分母固定
   理由：分母固定 ⇒ H 与 D_KL 可查表精确算；最大余数法 ⇒ 无 dust、无顺序依赖

2. 温度重标定（校准）
   T = CALIBRATION[model_fingerprint][template_id][class_id]     // Q32，版本化表
   q'_i ∝ q_i^(1/T)                            // 定点幂：log 域做，查表
   依据：llm-storytelling §2 末段"模型给出的自报概率不是校准的概率……
        必须先在有真值的小场景上做一次校准，校准曲线本身要进 Phase 0 的交付物"

3. ε-混合（保证支撑集与 π 相同）
   ε = 1/8                                     // ［本文原创，D 级］
   p_i = (1-ε)·q'_i + ε·π_i
   作用：(a) 任何 option 都不会被 LLM 归零 ⇒ Gumbel abduction 良定；
        (b) LLM 不能对任何一个规则认为可能的动作行使否决权；
        (c) 与 π 的下界一起，把每次调用的 D_KL 钉死在 ≤ 6 bit（L5）

4. 量化到 Q32 并写 ledger
   p_final_q32[i] = round_q32(p_i)，最大余数法补齐使 Σ == 1<<32
```

**校准协议（Phase 0 交付物）**：
- 校准集：一组**有真值动作分布**的微场景。可用的只有两类：(a) 有解析解的玩具博弈（最后通牒、公共品、信任博弈）；(b) 从 Seshat 的分布级频率反推的"结构条件 → 动作频率"配对。**注意 (b) 是 `π` 的校准目标，用它同时校准 `p_LLM` 会造成循环**——见 §附录 A 开放问题 O2。
- 指标：ECE（期望校准误差，10 桶）与 SD-ratio（模型给出的分布标准差 / 真值分布标准差）。
- 验收：ECE ≤ 0.10；SD-ratio ∈ [0.8, 1.25]。**［D 级待标定］**。这个区间的选取依据是实证观测到的两个极端：未干预时 SD-ratio 落在 0.4–0.56，Verbalized Sampling 干预后矫枉过正到 1.26–1.37（`llm-agent-social-simulation` §4 表〔R2〕行，源 arXiv:2510.01171）。取 [0.8, 1.25] 意为"既没坍缩也没矫枉过正"。
- 校准表 `CALIBRATION` 是版本化资产，其哈希进世界线身份。**换模型 ⇒ 校准表作废 ⇒ 必须重标定**。

### 2.8 失败处置：为什么是"从 π 采样"而不是"取 NOOP"（裁决 L4）

这是本节唯一一条**反直觉但可以证明**的规范。

设某决策类的行动概率为 `a`，调用失败率为 `f`。两种处置：

```
处置甲（失败 → NOOP）:  P(行动) = (1-f)·E_p[act]
处置乙（失败 → 从 π 采样）: P(行动) = (1-f)·E_p[act] + f·E_π[act]
```

对预算敏感度 `β = d(事件数/世纪)/d(调用数/世纪)`（§4.4 要测的量），调用数与 `(1-f)` 成正比，于是：

```
处置甲:  β = E_p[act] / (调用数上限)          ≠ 0，且与 LLM 是否有偏无关
处置乙:  β = (E_p[act] - E_π[act]) / (调用数上限)
```

**处置甲让 β 恒不为零，于是 β 这个指标就永远测不到我们真正想测的东西**（LLM 与规则先验在"行动倾向"上的差）。处置乙让 β 恰好等于我们想测的那个差除以一个已知常数。

推论（同样重要）：**这也意味着"关掉 LLM" 与 "LLM 全部失败"在事件率上是同一件事**，于是 §4.3 的滚动短窗孪生与 §4.4 的预算敏感度实验测的是同一个量的两个投影，可以互相校验。

**因此 `FallbackCode` 的每一种取值都走同一条路径：**

| `FallbackCode` | 触发 | 处置 |
|---|---|---|
| `BUDGET_EXHAUSTED` | 本 tick / 本世界线配额用尽 | 从 `π` 采样 |
| `TIMEOUT` | 批处理未在窗口内返回 | 从 `π` 采样 |
| `PARSE_FAIL` | 结构化输出不合 schema | 从 `π` 采样 |
| `LINT_REJECT` | 渲染期 lint 命中（§7.4） | 从 `π` 采样 |
| `REFUSAL` | 模型拒答（`stop_reason == "refusal"`） | 从 `π` 采样 |
| `CALIBRATION_MISSING` | 该 (model, template, class) 无校准条目 | 从 `π` 采样 |
| `NOT_ELIGIBLE` | 调度器判定不走 LLM | 从 `π` 采样（不是"走 default_policy"，见下） |

**`REFUSAL` 值得单列**：`llm-storytelling` §1 通道表第 15 项"拒答 / 软化（对齐层删掉一整类历史内容）"是一条真实的、方向已知的污染通道——前沿模型会对屠杀、奴隶制、人祭、酷刑一类内容拒答或软化，而这些恰恰是前工业史的常规内容。若处置是 NOOP，则**世界会系统性地少发生残酷的事**。处置乙让拒答率变成一个纯粹的成本损失而不是一个历史偏置。**必测项**：`refusal_rate` 按决策类分层统计。任何决策类的 `refusal_rate > 0.05` 都必须书面记录，并在该类上把 `llm_eligible` 置为 false（因为该类的 LLM 样本已经不是随机缺失）。

**`NOT_ELIGIBLE` 为什么也是"从 π 采样"而不是"走 default_policy"**：`default_policy` 是一个确定性策略函数，用于 `MODE_HEADLESS`（§8.5）。在 `MODE_FULL` 里混用两种机制会让"LLM-on 线"内部的决策机制不同质，破坏 §4.3 的配对比较。规范：**`MODE_FULL` 里非 LLM 决策点一律从 `π` 采样；`MODE_HEADLESS` 里一律走 `default_policy`；两种模式不混用。** 并且必须满足一致性约束：`default_policy(s)` 的动作分布在长期平均意义上应当逼近 `π(·|s)`，偏差进监控（`policy_prior_gap`，D 级阈值 0.05 TVD）。

### 2.9 `novel_action_request` 审批通道

```
NovelActionRequest {
  request_id     : H128
  site_id        : H128
  tick           : Tick_y
  expressed_as   : [(PrimitiveVerb, [Arg])]     // 必须用现有 P1..P10 表达
  why_not_in_A   : [RejectCode]                 // 规则侧填，不是模型填
  model_note_hash: H256                         // 模型的说明存渲染域，只留哈希
}
```

**七条规范：**

1. **本次运行零效力。** 请求写入渲染域的一个 append-only 队列，对世界状态无任何影响。当前 tick 按 §2.8 从 `π` 采样。
2. **模型说明只留哈希。** 请求里没有任何模型产出的文本进入内核域或分析域。文本存渲染域，用于人审阅。
3. **两类缺口必须分开。**
   - `ENUMERATOR_GAP`：该动作**可以**由 P1–P10 组合表达，只是我们的 `A(state)` 枚举器漏了。这是 bug，修它 = 改枚举器 = 选择集变了 = **内核版本变更**。
   - `PRIMITIVE_GAP`：需要新原语。**推定拒绝**，走 `spec-world-state` §1.5 的准入争议裁决程序（五条准入规则：随附性检验、参数类型白名单、禁读标签、写集静态可判、类型抹除不变）。
4. **批准的代价是世界作废。** 任何被批准的修改都改变了 `A(state)`，因此改变了 `π`，因此改变了历史。按 `mandate-contradictions` F9："机制变更 ⇒ 该世界作废，必须从 t=0 重跑。"**这个代价就是这条通道的安全机制**——它使"让 LLM 开一个新口子"永远不是一个便宜的操作。
5. **禁止回灌。** 请求内容永不进入任何后续 prompt、永不成为 `Proposition`、永不出现在因果图。（§11 的硬约束在这里有一个具体落点。）
6. **`novel_request_rate` 是对我们的诊断，不是对模型的诊断。** 持续偏高 = `A(state)` 太窄，模型被迫把复杂动机压进错误的枚举格（`llm-agent-social-simulation` M1 失效条件的"制度性误译"）。
7. **`novel_request_rate` 恒等于 0 也是症状。** 三千年一次都没有，多半说明 prompt 里有一句话教会了模型不要问。必测：在提示词改写敏感性检验（§7.6）的三个模板上，`novel_request_rate` 的差异必须在噪声内。

**阈值（［D 级待标定］）**：`novel_request_rate ∈ [0.002, 0.05]`（每次调用）。低于下界查 prompt，高于上界查枚举器。

### 这一节禁止了什么

- 禁止把"要不要发生"问给 LLM。规则的 `λ_c(结构)` 先掷骰，掷中才唤醒模型。
- 禁止 LLM 输出一个选择（one-hot 被记为退化并监控）、一个数字、一个绝对年份、一段自由文本作为可裁决内容。
- 禁止 `A(s)` 里没有 NOOP，禁止 `π(NOOP)` 在无结构压力时小于 0.5，禁止 `|A| > 64`，禁止 `π_i < 2⁻⁶`。
- 禁止任何一种调用失败被处置成 NOOP——包括超时、超配额、拒答、解析失败。
- 禁止未校准的 `p_LLM` 直接进采样（`CALIBRATION_MISSING` 即降级）。
- 禁止 `π` 里出现 `justification_class = 叙事` 的项（CI 断言数量为 0）。
- 禁止 `π` 的触发器与先验引用叙事节拍变量。
- 禁止 `novel_action_request` 在本次运行产生任何效力，禁止它的文本回流。
- 禁止在 `MODE_FULL` 里混用 `π` 采样与 `default_policy`。

## 3. LLM 影响力比特预算

### 3.1 三个量的定义（全部定点、全部在 ledger 里可重算）

对一次 LLM 决策 `k`（选择集 `A_k`，规则先验 `π_k`，采样分布 `p_k = p_final`，实现动作 `a*_k`）：

```
操纵比特（steering）      B_k = D_KL(p_k ‖ π_k) = Σ_i p_ki · log₂(p_ki / π_ki)        ≥ 0
熵亏损（collapse）        E_k = H(π_k) − H(p_k)                                       可正可负
实现意外度（surprisal）   S_k = −log₂ π_k(a*_k)                                        ≥ 0
```

按世纪聚合：`B = Σ_{k∈世纪} B_k`，`E = Σ E_k`，`S = Σ S_k`，`H_π = Σ H(π_k)`。

**任务书要求的 `narrative_bits_per_century` 就是 `S`。** 下一小节证明它为什么不能单独用。

### 3.2 恒等式：任务书的指标恰好等于"操纵减坍缩"

`a*_k ~ p_k`，所以

```
E[S_k] = E_{a~p_k}[−log₂ π_k(a)] = H(p_k, π_k)                  （交叉熵）
       = H(p_k) + D_KL(p_k ‖ π_k)
       = H(π_k) − E_k + B_k
```

对世纪求和：

> **`E[S] = H_π + B − E`**，等价地 **`S_excess ≜ E[S] − H_π = B − E`**

三个后果：

1. **`S` 的零假设期望不是 0，是 `H_π`。** 一条完全没有 LLM、纯从 `π` 采样的世界线，它的 `Σ −log₂ π(a*)` 期望恰等于 `Σ H(π)`，可以是每世纪几百上千比特。**因此报告 `S` 的原始值毫无意义**；唯一有意义的形式是 `S − H_π`。任何把 `Σ −log₂ π(a*)` 当作"叙事比特"直接汇报的仪表盘，报的是规则自己的熵。
2. **`S_excess` 是 `B` 与 `E` 的差，两种病理在它里面相互抵消。** 一个同时在操纵（`B = 200 bit`）和在坍缩（`E = 200 bit`）的模型，`S_excess = 0`，看起来完全清白。这是 `llm-storytelling` F5"指标是单边的"那句话的精确形式：不只是"永远选众数得 0 分"，而是**任意满足 `B = E` 的病理组合都得 0 分**，而 `B = E` 恰恰是"典型化偏置"的自然形态（把概率质量从尾部搬到众数上：既提高了 `D_KL`，又降低了熵，两者同量级）。
3. **`S` 有一个 `B`、`E` 都没有的独门用途：ledger 完整性审计。** 见 §3.5。

### 3.3 预算的分母：为什么全局比值是空的

任务书要求"与规则 RNG 注入熵之比"。必须先算一遍这个比值的量级，否则会设一个恒真的约束。

用 `spec-world-state` 的实体上限做算术：

```
决策点总数/世纪（规则侧）
  Household ≤ 2×10⁵，每年 1 次策略抽样            → 2×10⁷ 决策/世纪
  Person（L2）≤ 3×10⁴，每年 ~4 次                  → 1.2×10⁷ 决策/世纪
  合计 ≈ 3.2×10⁷ 决策/世纪
每个决策的先验熵 H(π) ≈ 0.5–1.5 bit（NOOP 主导的分布）
  ⇒ H_dec ≈ 1.6×10⁷ ~ 4.8×10⁷ bit/世纪

LLM 调用数/世纪（配额 10 次/tick，tick = 年）      → 1×10³ 次/世纪
每次调用 D_KL 上限 6 bit，实测目标均值 ≤ 1 bit
  ⇒ B ≈ 10³ bit/世纪（上限 6×10³）

全局比值 ρ_global = B / H_dec ≈ 10³ / 3×10⁷ ≈ 3×10⁻⁵
```

**`ρ_global ≈ 3×10⁻⁵`。任何"比值 ≤ 1%"之类的约束都会自动通过，因此是空约束。** 这不是说 LLM 没有影响——而是说 1000 次落在**高杠杆决策点**上的调用，可以支配一部历史，同时只贡献决策熵的十万分之三。**信息量守恒不适用于因果杠杆。**

### 3.4 预算的正确形式：按决策类分账（［本文原创，无来源，D 级］）

```
对每个决策类 c ∈ CLASS_REGISTRY（战争发起、制度提案、教派分裂、继承争议、
                                 迁移决策、贸易缔约、镇压/宽赦、背叛/结盟…）:

  H_dec,c = Σ_{k ∈ c, 本世纪} H(p_k)        // 该类全部决策点（含非 LLM 点，用 π）
  B_c     = Σ_{k ∈ c ∩ LLM, 本世纪} B_k
  ρ_c     = B_c / H_dec,c
```

同类同量纲、同一批决策点，比值有意义。用同一套上限估：某世纪战争发起类有 50 个政体级 Actor，每个每年 1 个决策点 ⇒ 5000 决策/世纪，`H ≈ 1.5 bit` ⇒ `H_dec,c ≈ 7500 bit`；其中 LLM 触及 300 个，`B_c ≈ 300 bit` ⇒ **`ρ_c ≈ 0.04`**。与建议上限同量级——这才是一个会被触发的约束。

**预算表（全部 ［D 级待标定］，标定协议见 §4.5）：**

| 量 | 硬预算 | 报警线 | 说明 |
|---|---|---|---|
| `B_k`（单次调用） | ≤ 6 bit | — | 由 `π_min = 2⁻⁶` **结构性保证**，不是靠检查 |
| `mean_k B_k`（世纪均值） | ≤ 1.0 bit | 0.7 bit | 相当于"平均每次调用把先验的赔率移动 2 倍" |
| `B`（世纪总量） | ≤ 1000 bit | 700 bit | = 配额 × 均值上限 |
| `ρ_c`（每决策类） | ≤ 0.05 | 0.035 | §3.3 的算术给出量级 |
| `ρ_global` | **不设上限，禁止单独汇报** | — | 恒 ≈ 3×10⁻⁵，是空约束（§3.3） |
| `E / H_π`（熵亏损占比） | ∈ [−0.25, +0.25] | ±0.18 | 双侧。正超限 = 坍缩；负超限 = 矫枉过正。区间由 SD-ratio 的实测极端（0.4–0.56 / 1.26–1.37，`llm-agent-social-simulation` §4 表〔R2〕）映射而来，映射本身 D 级 |
| `S_excess`（= `B − E`） | **无独立预算** | — | 只作为 §3.5 完整性审计的输入 |

### 3.5 采样一致性审计：`S` 的唯一正当用途（［本文原创，无来源，D 级］）

`S` 不能当污染指标，但它能当**账本真实性的检验**：如果 ledger 里记录的 `p_final` 与实际掷出的 `a*` 不一致（PRNG 接错流、`p_final` 被事后改写、量化实现有 bug、某处偷偷用了 NOOP 兜底），`S` 的经验分布就会偏离它在 `p_final` 下的理论分布。

**T-SAMPCONS（每世纪、每决策类）：**
```
H0: a*_k ~ p_k（ledger 记录的分布）
统计量: 把每次调用按 p_k(a*_k) 的十分位分桶，做 G 检验（似然比卡方），df = 9
判据: 每决策类、每世纪的 p 值不得连续 3 次 < 0.01
补充: 直接比较 mean(S) 与 mean(H(p_k,π_k))，|差| / SE < 3
```
这条检验能抓住 `llm-storytelling` F5 提到但没给检法的那件事——**"这里根本没有种子，只有一次 API 调用"**。如果有人把三段式退化成"让模型直接说选哪个"，`p_final` 就不是真正的采样分布，T-SAMPCONS 会在几百次调用内失败。

### 3.6 越界的两种合法处置，以及"第三种"长什么样

`llm-storytelling` §2 表格末行：**超限只有两个合法处置：承认 `π` 错了（去改规则），或强制按 `π` 采样。不允许第三种处置（"这次就算了"）。**

可执行形式：

```
每世纪结算时，若 B > B_budget 或 ρ_c > ρ_max：
  路径 A（改规则）:
      必须提交一个 π 修订，附 justification_class ∈ {外部数据拟合, 理论推导, 量纲/守恒约束}
      justification_class = 叙事 的修订被 CI 拒绝
      π 修订 ⇒ 内核版本变更 ⇒ 世界作废，从 t=0 重跑（mandate-contradictions F9）
  路径 B（强制先验）:
      该决策类在本世界线剩余全部 tick 上 llm_eligible := false
      即：从此按 π 采样，且这一事实写进世界线 manifest 的显著位置
```

**"第三种处置"在这个项目里的具体长相，必须写下来才能被识别：**

| 伪装 | 为什么它是第三种处置 |
|---|---|
| "把 `B_budget` 从 1000 调到 1500" | 改的是仪表不是世界 |
| "这个决策类的 `π` 本来就不准，先不计入预算" | 选择性豁免 = 无预算 |
| "把 `ε` 从 1/8 调到 1/4 让 `D_KL` 降下来" | ε-混合确实降 `D_KL`，但它同时降的是 LLM 的全部影响力——如果这是想要的，就应该走路径 B 并说明；如果只是为了让指标变绿，它是伪造 |
| "换一个更听话的模型" | 换模型 ⇒ 校准表作废 ⇒ 必须重标定 ⇒ 若不重标定就是伪造 |
| "这个世纪的超限是因为发生了一场大战，情有可原" | 这句话的字面意思是"戏剧性时刻允许更多 LLM 影响"，即 `pseudo-simulation` S8/`llm-agent-social-simulation` AP7 的剧情通道 |

治理条款：**`B_budget`、`ρ_max`、`ε`、`π_min`、`|A|` 上限一旦用于任何已发布的世界线，就进入版本冻结**（`llm-storytelling` F6 第 4 条"控制组冻结"纪律的推广）；修改必须开新的指标基线并说明理由，`git blame` 每一次修改进 `spec-validation` 的参数改动分类账（`pseudo-simulation` F2 判别测试 1）。

### 这一节禁止了什么

- 禁止把 `Σ −log₂ π(a*)` 作为污染指标单独汇报——它的零假设期望是 `H_π`，不是 0。
- 禁止只报单侧量。`B`、`E`、`S` 三者必须同时出现在同一张表上，且必须校验恒等式 `E[S] ≈ H_π + B − E`。
- 禁止汇报 `ρ_global`。它恒 ≈ 3×10⁻⁵，是一个专门用来让人放心的数字。
- 禁止用扩大选择集 `|A|` 或抬高 `ε` 的方式降低 `D_KL` 而不同时声明影响力被削弱。
- 禁止超预算后的任何非 A 非 B 处置，包括"调阈值""选择性豁免""换模型""事出有因"。
- 禁止在没有 T-SAMPCONS 的情况下相信 ledger 里的 `p_final`。

## 4. 事件基率污染的检测

### 4.1 要防的东西的准确形式

`llm-storytelling` §0 第二判决改写了威胁模型，这一改写是本节全部设计的前提，必须原样保留：

> **要防的不是"戏剧性"，是"任何系统性偏置进入不该由它决定的量"。** 我们不需要先证明 LLM 偏向戏剧，才有理由不让它裁决——只要它有**任何**方向的系统性偏置，把"事件是否发生"交给它就等于把这个偏置注入成一棵隐藏剧情树。同时，我们必须把"世界太合理、文明太雷同"当作与"世界太狗血"**同等级别**的 bug 来监控。

实证背景（全部转引自 `llm-storytelling` §0 证据表，等级为该表自标）：persona 分布坍缩（集中度 0.36→0.69、熵 1.46→0.77、TVD 0.44、85% 场景坍缩、~80% persona 默认选最便宜项，Ozkan 2026 arXiv:2607.18310，**C**）；typicality bias（标注者 51.6–60.8% 偏好典型回答，arXiv:2510.01171，**A**）；生成式 AI 降低集体多样性（Doshi & Hauser 2024, doi:10.1126/sciadv.adn5290，**A**）；RLHF 显著降低输出多样性（Kirk et al. arXiv:2310.06452，**A**）；合成调查方差显著低于真实（Bisbee et al., *Political Analysis* 32(4):401–416, doi:10.1017/pan.2024.5，**A**）；前沿助手一致存在迎合（Sharma et al. arXiv:2310.13548，**A**）；agent 对负面社会线索从众性强于真人（OASIS arXiv:2411.11581，**A**）。

因此本节的**监控是双向的**：每一个指标都有下界和上界，"世界太安静"与"世界太吵"都触发同一套处置。

### 4.2 主检测器：决策点级配对比较（不需要任何对照组）

`llm-storytelling` F6 替代设计第 1 条："把比较从世界级降到决策点级……这是配对比较，不受世界发散影响，样本量等于决策次数（很大），统计功效高得多。这是 off-policy evaluation 的标准做法。"

```
对每个决策类 c、每个世纪：
  样本 = 该类全部 LLM 决策点 k
  逐点量：Δ_act,k = p_k(ACT) − π_k(ACT)          // ACT = A_k \ {NOOP} 的总概率
          B_k, E_k（§3.1）
          ΔH_k = H(p_k) − H(π_k)

  报告：mean(Δ_act) ± SE，符号检验，Wilcoxon 符号秩
        mean(B), mean(E), 以及 B 在各 option verb 上的分解
```

**判据（［D 级待标定］）：**

| 指标 | 通过区间 | 越界含义 |
|---|---|---|
| `mean(Δ_act)` | \|·\| ≤ 0.03，且 Wilcoxon p > 0.01 | 正 = 基率被抬高（"制造事件"）；负 = 世界被抹平（按 §4.1 的证据**更可能**） |
| `mean(B)` | ≤ 1.0 bit | §3.4 |
| `mean(E)/mean(H(π))` | ∈ [−0.25, 0.25] | 正 = 坍缩；负 = 矫枉过正 |
| `Δ_act` 在决策类之间的方差 | 显著 > 0 | 若各类的 `Δ_act` 完全一致，说明 LLM 没在响应处境，只在响应模板 |

**这个检测器不需要孪生线、不需要控制组、不需要世界跑完**。它在第一批 1000 次调用之后就有统计功效。它是本节的一等公民。

**它测不到什么（必须写下来）**：它是**逐点**的，因此看不见**构成效应**——LLM-on 的世界发展得更快/更慢，于是产生了更多/更少的战争决策点。`Δ_act` 可以恒为 0，而 LLM-on 的世界每世纪的战争数是 LLM-off 的三倍，仅仅因为它有三倍多的政体。这就是下一小节存在的理由。

### 4.3 孪生线的正确定位：有界区间内的构成效应分母

**先直接回答任务书那句话。**

任务书要求"说明为什么孪生线是所有分布层指标的分母，没有它一个都测不了"。这句话在两个意义上不成立，在一个意义上成立，必须分开说：

**(1) "所有分布层指标"——不成立。** §4.2 的决策点级比较是分布层指标（它比较的是两个分布 `p` 与 `π`），它完全不需要孪生线。`llm-storytelling` F6 替代设计第 1 条就是为了取代那个分母而写的。

**(2) "没有它一个都测不了"——不成立，且方向危险。** `mandate-contradictions` 决定 8 写了这句话（"没有孪生线，所有污染指标都失去分母"），但它引的是 `llm-storytelling` 的**旧稿**，而 F6 正是那份旧稿的自我推翻，给出两个独立致命缺陷：
- *缺陷一*：分叉后两条线不是同一个世界。"`f_on / f_off` 在分叉几百年后测的是'两个世界有多不同'，而不是'LLM 注入了多少偏置'"；而且它有确定的方向性错误——任何让世界更复杂的机制都会同时提高几乎所有事件率。
- *缺陷二*：控制组是我们自己写的，可以被拟合。"有人会去调默认策略，直到比值落进阈值。这时我们把对照组拟合到了处理组上，指标从此永远绿灯，而两条线可以同时是错的。"

**(3) 成立的那一部分：孪生线是唯一能测"构成效应"的东西，但只在一个有界区间内有效。** §4.2 的盲区（构成效应）在原理上需要一个"同一个世界，只有 LLM 这一个变量不同"的对照。孪生线是唯一的候选。问题只在于它在什么时间尺度上还是"同一个世界"。

**因此本规格的裁决：滚动短窗配对孪生（rolling short-window paired twin）。**

```
定义 相干视界 T_coh(Y)：
  对观测量 Y，取空干预对照分布 D_placebo,Y(Δ)（causality-bookkeeping F5：
  同 tick、同机制类、可比空间位置上随机选另一抽样点做同类型翻转，重复 ~100 次）。
  T_coh(Y) = max{ Δ : D_placebo,Y(Δ) < 0.5 × 我们想检出的效应量 }
  —— 即"两条线还没被自身噪声淹没"的时间窗。

协议：
  1. 主线 M 在 MODE_FULL 下跑满 3000 年，记录 ledger。
  2. 在 t ∈ {50, 100, 150, …, 2950}（每 50 年，共 59 个分叉点）各分出一条支线：
       - 支线 Off_t：从 t 起 llm_causal_enabled := false（Intent 全部从 π 采样），
         跑 W = min(50, T_coh) 年
       - 支线 Null_t：从 t 起什么都不改（空干预），跑 W 年 —— 这是噪声地板
     三条线在 [t, t+W] 内共用同一个 CBRNG 键空间（只有 agent/llm_sampling 流不同）。
  3. 在每个窗口内统计 event_rate_ratio_t = f_on(t..t+W) / f_off(t..t+W)
     并统计 null_ratio_t = f_on(t..t+W) / f_null(t..t+W)   —— 理论上 ≡ 1
  4. 跨 59 个窗口做配对分析（窗口是配对单位，不是年）。
```

**为什么这修复了两个缺陷：**
- *缺陷一*：`W ≤ T_coh` 保证窗口内两条线还是同一个世界；59 个窗口给出真实的样本量（原方案样本量是 1）；配对结构吸收了世界状态的漂移。
- *缺陷二*：`Off_t` 支线用的是 **`π` 采样**，不是"我们写的默认策略"（§2.8 的 `NOT_ELIGIBLE` 处置）。`π` 已经在 §2.3 被约束为"必须拟合、不得撰写、`叙事` 类为 0、`P/T ≤ 3`"，因此它不是一个可以随手调到达标的对照组——调它要走 §3.6 路径 A，代价是世界作废。**这就是把"控制组冻结"从一条纪律变成一条结构。**

**判据：**

| 指标 | 通过区间 | 备注 |
|---|---|---|
| `event_rate_ratio`（59 窗口的配对几何均值） | **∈ [0.8, 1.25]** | 任务书给的区间，本文采纳。注意它现在的含义变了：不是"整条历史线的事件率之比"，而是"短窗内构成效应的配对估计" |
| `null_ratio` | ∈ [0.95, 1.05] | **必须先通过这一条**。若空干预支线与主线的事件率就已经差 20%，说明 `T-ISOLATE`（`spec-world-state` §3.4）没过，或 `W` 取大了 |
| `event_rate_ratio` 随分叉后时间的曲线 | 不得单调发散 | F6 可观察症状第 1 条："如果它随时间单调发散，说明这个比值在测世界差异而不是测污染" |
| `event_rate_ratio` 在决策类之间 | 分层报告，不许只报总数 | 总数会把"战争多了 30%、饥荒少了 30%"平均成 1.0 |

**成本**：59 个分叉点 × 2 支线 × 50 年 = 5900 模拟年 ≈ 主线的 2 倍。这笔钱必须进 `spec-validation` 的算力预算（`mandate-contradictions` 决定 20 的 5:4:1 里的"验证"那 4 份）。

**明确降级用途（F6 第 3 条原文）**：孪生线只用于 (a) 空反事实的噪声地板；(b) 分叉后短窗口的分布对比。**不得用作长期指标的分母。**

### 4.4 预算敏感度 `budget_sensitivity`

`llm-storytelling` F1 可观察症状第 1 条称它是"最便宜的一发子弹"，"这个实验一天就能做，不需要等系统完整"。

```
定义: β = d(事件数/世纪) / d(调用数/世纪)

协议:
  同一 world_seed，配额 Q ∈ {0, 0.25Q₀, 0.5Q₀, Q₀, 2Q₀}，Q₀ = 10 次/tick
  每个配额跑同样的 59 个滚动短窗（复用 §4.3 的窗口结构）
  对每个决策类 c，回归  events_c/世纪 ~ β_c · calls/世纪 + γ_c
  归一化: β̂_c = β_c · Q₀ / (events_c/世纪 at Q₀)
          即"把配额从 0 加到 Q₀，事件密度相对变化多少"

判据: |β̂_c| ≤ 0.10，全部决策类       ［D 级待标定］
      报警线 0.07
```

**与 §4.2 的一致性交叉检验（这是本节最有用的一条）**：由 §2.8 的失败处置恒等式，

```
β̂_c ≈ (E_p[act] − E_π[act]) / E_π[act] = mean(Δ_act,c) / π̄_c(ACT)
```

即 **`β̂` 与 `mean(Δ_act)` 必须一致**（在构成效应可忽略的短窗内）。二者的差就是构成效应的估计：

```
composition_effect_c ≜ β̂_c − mean(Δ_act,c)/π̄_c(ACT)
```

**这是本规格对"孪生线到底测什么"的最终回答**：孪生线（经由 `β̂`）减去决策点级配对（`Δ_act`），剩下的就是构成效应，而构成效应是逐点比较**在原理上**看不见的那一块。两个检测器都需要，且它们互相校验。若 `composition_effect` 显著非零而 `Δ_act ≈ 0`，结论是"LLM 没有改变任何一次决策的倾向，但改变了世界产生决策的速率"——这是一个真实的、值得报告的发现，也是 F1 那条论证的最纯粹形态。

**必须同时做的另一件事（否则 β 会骗人）**：配额变化会改变**哪些**决策点走 LLM（调度器按 `topk` 挑）。因此每个配额档的 LLM 决策点集合不同，`β̂` 里混了选择效应。修正：在 `Q = 2Q₀` 的运行里记录**每个决策点是否会在 `Q₀` 下被选中**，只在"两档都会被选中"的子集上重算 `Δ_act`；差额即选择效应。这一条 `llm-storytelling` 没有提到 —— **［本文原创，无来源，D 级］**。

### 4.5 `noop_rate` 与事件间隔的形状

**(a) `noop_rate`**（三个量，都要报）

```
L0_noop_rate  = 1 − (创建的决策点数) / (Actor × 年 × 决策类)      // 规则侧，机会都没出现
L1_noop_rate  = (a* == NOOP 的次数) / (决策点数)                    // 出现了但没动
Δ_noop        = mean(p_k(NOOP)) − mean(π_k(NOOP))                   // LLM 的推动方向
```

| 指标 | 目标 | 依据 |
|---|---|---|
| `L0_noop_rate` | ≥ 0.99（政体级决策类） | 由 `λ_c` 对 Seshat 的战争起始率拟合决定，**不是**我们设的。在拟合完成前用 0.99 ［D 级占位］ |
| `L1_noop_rate` | ≥ 0.85（政体级）；分层报告 | 由 `π(NOOP) ≥ 0.5` 与实测的 `Δ_noop` 共同决定；0.85 ［D 级待标定］ |
| `Δ_noop` | \|·\| ≤ 0.03 | 与 `mean(Δ_act)` 是同一个量取负号，一致性可校验 |
| `L1_noop_rate` 随模拟年份 | 不得单调下降 | 单调下降 = 世界越跑越忙 = 典型的调用驱动症状 |

`mandate-contradictions` F11 压力点表第 2 行要求："事件密度是**输出**不是参数；'无事发生'必须显式占概率质量；密度随时间的曲线进预注册。" 上表就是这句话的可执行形式。

**(b) 事件间隔的形状**（`llm-storytelling` F1 可观察症状第 3 条）

> 结构驱动的风险率过程会产生**过度分散**（over-dispersed）的间隔（丛集 + 长静默）；调用驱动的会产生接近几何分布的间隔。这两者用 Fano factor 就能分开。

```
Fano factor  F = Var(N_century) / E(N_century)     // N = 每世纪该类事件数

判据（［D 级待标定］）:
  F ≥ 2.0            // 结构驱动应当明显过度分散
  F(LLM-on) ≥ 0.8 × F(LLM-off)    // LLM 不得把丛集抹平
```
第二条比第一条重要：`F` 的绝对值取决于我们的 `λ` 写得对不对（那是 `spec-validation` 的事），但 **`F` 在 LLM 打开后掉下来**，只可能是 LLM 造成的。

**(c) 标定协议（把上面所有 D 级数字变成有依据的数字）**

Phase 1 必做，顺序不能反：

1. 先在 `MODE_HEADLESS` 下跑 200 个种子 × 3000 年，测出全部指标的**规则侧基线分布**。这一步完全不花 LLM 的钱。
2. 用 Seshat 的分布级目标拟合 `λ_c` 与 `π`，重跑第 1 步，直到规则侧基线落在目标区间内。
3. **此时才第一次打开 LLM**，跑 §4.3 的滚动短窗，把上表的所有阈值按"规则侧基线的 ±k×SD"重新定义，而不是按我拍的数字。
4. 阈值一旦用于任何已发布结论即冻结（§3.6 治理条款）。

**顺序不能反的理由**：如果先开 LLM 再定阈值，阈值就是按 LLM 的实际行为定的，指标从此永远绿灯——这是 `llm-storytelling` F6 缺陷二在阈值层面的复现。

### 4.6 三条腿必须同时站着

`llm-storytelling` F6 替代设计第 2 条："决策点级比较只能告诉我们'LLM 和我们的规则谁更极端'，不能告诉我们**谁对**。要回答后者必须有世界之外的锚。"

| 腿 | 测什么 | 需要对照组吗 | 能否回答"谁对" |
|---|---|---|---|
| **A. 决策点级配对**（§4.2） | LLM 相对 `π` 的逐点偏置 | 否 | 否 |
| **B. 滚动短窗孪生 + 预算敏感度**（§4.3/4.4） | 构成效应；事件密度对调用数的弹性 | 是（但是短窗、配对、`π` 采样对照） | 否 |
| **C. 外部经验锚**（Seshat 分布级） | `λ` 与 `π` 自身对不对 | 外部数据 | **是**（唯一的一条） |

**三条腿缺任何一条，剩下两条都会给出可以自洽但错误的绿灯。** 只有 A：LLM 和我们的规则一致，而两者可以同时错。只有 B：短窗对照通过，而 `π` 本身被编排（`llm-storytelling` F7）。只有 C：`π` 拟合得很好，而 LLM 在运行时把它整个推歪。

### 这一节禁止了什么

- 禁止把 LLM-on/LLM-off 的**长期**事件率之比当作污染指标的分母。
- 禁止只有一条孪生线、只有一个分叉点。滚动短窗、配对、`W ≤ T_coh` 是强制的。
- 禁止在没有先通过 `null_ratio ∈ [0.95, 1.05]` 的情况下解读任何 `event_rate_ratio`。
- 禁止用"我们写的 `default_policy`"当孪生线的对照机制；对照必须是 `π` 采样。
- 禁止调 `default_policy` 或 `π` 的参数以使 `event_rate_ratio` 落进阈值（这是 F6 缺陷二的原型）；任何此类修改走 §3.6 路径 A，代价是世界作废。
- 禁止先开 LLM 再定阈值。
- 禁止把事件率指标聚合成一个总数汇报；必须按决策类分层。
- 禁止只监控"事件太多"。"事件太少""文明太雷同""间隔太规则"是同等级别的 bug，用同一套处置。
- 禁止在只有一条腿（A 或 B 或 C）的情况下宣称"未检出污染"。

## 5. 命名与文化创造：从 authoring 降级为 verbalization

### 5.1 为什么命名权必须整体收回

`llm-storytelling` F3 的失败机制：**LLM 关于"一个东亚季风河谷的农业君主制需要什么样的正当性叙事"的条件分布，其众数就是真实的中国思想史。不是它偷偷抄，是这就是它学到的东西。** 机制证据：Durmus et al.（GlobalOpinionQA, arXiv:2306.16388，**A**）——用国籍 prompt 引导会让输出移动，但**有时移向的是刻板印象**，且单纯翻译**不能**可靠地把输出移向该语言使用者的观点；Larooij & Törnberg 2025（*AI Review*, doi:10.1007/s10462-025-11412-6，**A**）在 ABM 语境下把它命名为 selection bias 与 data leakage——"LLM 可能复制历史模式，或复现既有研究结论，而不是动态生成行为"。

F3 列出的五条具体泄漏（该文自标 D 级推断，但验证成本极低）：概念（"天命"及其整套语义网络）、构词法（年号/谥号的汉语构词）、文体（格言体/悖论体）、现代观念偷渡（青铜时代先知讲平等与同理心）、**书写层泄漏**（"把 `/tavix/` 写成'塔维'是中性的，写成'天维'就把'天'的整套语义送了进去"）。

`llm-agent-social-simulation` §6.4 给出同向结论并加一句本项目特有的：**目前没有针对东亚/中国历史语境的 LLM 偏差评测**（该简报两轮检索均未找到），所以我们对"LLM 扮演公元前的黄河流域首领会怎样偏"**没有任何量化依据**。这不是"风险较小"，这是"风险未知且不可估计"。在这种条件下，唯一可辩护的工程立场是把这条通道整体关掉，因为关掉它的成本极低（一个音系引擎），而它失败的后果是整个项目的立项前提失效。

### 5.2 世界内音系 / 构词 / 规则音变引擎（规格）

**位置**：内核域。它是 `spec-world-state` §2.3.7 中 `Named(entity, symbol_id)` 里 `symbol_id` 的**唯一**生产者。随机流：新增 `26 | worldgen/phonology`（创生期）与 `27 | lang/change`（运行期音变），进 `spec-world-state` §6.4 的封闭流表 —— 这是一个需要该 spec 接受的接口修改（见 §附录 C）。

#### 5.2.1 数据结构

```
PhonoInventory {
  id            : H128                    // = H128(canonical(全部字段))
  consonants    : [PhonemeSpec]           // 8 ≤ |C| ≤ 40
  vowels        : [PhonemeSpec]           // 2 ≤ |V| ≤ 12
  suprasegmental: { length: bool, nasalization: bool, tone_levels: u8 }  // tone_levels ∈ 0..5
}

PhonemeSpec {
  id       : u16                          // 引擎内部编号，不是字符
  features : FeatureBits                  // [±cons, ±son, place(6), manner(7), ±voice,
                                          //  ±asp, ±glot, height(4), backness(3), ±round]
  // 没有 IPA 字符串、没有拉丁字母：字符只在渲染层出现
}

SyllableTemplate {
  onset_min, onset_max   : u8             // 0..3
  coda_min,  coda_max    : u8             // 0..3
  nucleus_complexity     : u8             // 1 = 单元音, 2 = 允许双元音
  onset_class_mask       : FeatureMask    // 哪些特征组合可以做首辅音
  coda_class_mask        : FeatureMask    // 通常远严于 onset（跨语言强共性）
}

Phonotactics {
  sonority_slope_min : i8                 // 响度序列约束
  ocp_place          : bool               // 同部位相邻辅音禁止（必违条件的类型）
  harmony            : Option<{axis: FeatureAxis, domain: WordDomain}>   // 元音和谐
  max_word_syll      : u8
}

Morphology {
  strategy   : enum { ISOLATING, AGGLUTINATIVE_SUFFIX, AGGLUTINATIVE_PREFIX,
                      TEMPLATIC, FUSIONAL, POLYSYNTHETIC }
  slots      : [SlotSpec]                 // 每槽：语义范畴 + 形式集合 + 是否强制
  compounding: { productive: bool, head: enum{LEFT, RIGHT} }
  root_shape : SyllablePattern            // 如 CVC、CVCVC、C-C-C（三辅音根）
}

ProtoLang {
  id         : H128
  inventory  : PhonoInventory
  syllable   : SyllableTemplate
  phonotax   : Phonotactics
  morphology : Morphology
  stress     : enum { INITIAL, FINAL, PENULT, ANTEPENULT, WEIGHT_SENSITIVE, NONE }
  lexicon    : Map<ConceptId, FormId>     // cultural-evolution M9 的 LanguageState.lexicon
  typology   : Vector<Categorical>        // cultural-evolution M9 的 typology（独立演化）
}

SoundChange {
  id       : H128
  kind     : ChangeKind                   // 封闭枚举，见下
  target   : FeatureMask
  result   : FeatureDelta
  env_left : Option<FeatureMask>
  env_right: Option<FeatureMask>
  domain   : enum { ALL, STRESSED, UNSTRESSED, WORD_INITIAL, WORD_FINAL, CODA, ONSET }
  regularity : Q32                        // 1.0 = 新语法学派式完全规则；<1 = 词汇扩散
  applied_at : Tick_y
  community  : CommunityRef
}

ChangeKind ::= LENITION | FORTITION | ASSIMILATION | DISSIMILATION | DELETION
             | EPENTHESIS | METATHESIS | MONOPHTHONGIZATION | DIPHTHONGIZATION
             | UMLAUT | VOWEL_REDUCTION | CHAIN_SHIFT | TONOGENESIS | TONE_MERGER
             | CLUSTER_SIMPLIFICATION | REANALYSIS
```

**`TONOGENESIS` 值得单独说**：声调不是一个创生期参数，而是一个**可以从辅音格局演化出来**的后果（典型路径：韵尾喉塞/擦音丢失 → 前接元音获得音高对立 → 音高对立音位化）。规范：`tone_levels` 在创生期以高概率取 0，`TONOGENESIS` 只在满足结构条件（韵尾类别丢失且丢失前存在清浊或喉化对立）时才被 `lang/change` 流抽中。**这条设计的价值不在语言学准确性，而在于它让"这个世界有没有声调语言"成为一个演化结果而不是一个我们设的参数。**

#### 5.2.2 名字的产生

```
mint_symbol(concept: ConceptId, lang: ProtoLangId, ctr) -> SymbolId:
    // 1. 从该语言的构词法采样一个合法形式
    root  = sample_root(lang.morphology.root_shape, lang.inventory, lang.phonotax, ctr)
    form  = apply_morphology(root, concept.category, lang.morphology, ctr)
    // 2. 查重：同一语言内不得与既有形式冲突（同音词允许但受限）
    if collision_rate(form, lang.lexicon) > θ_homophone: retry (最多 8 次)
    // 3. 内容寻址
    return SymbolId = H128("sym" || lang.id || phoneme_sequence(form))
```

`SymbolId` 是**音位序列的哈希**，与任何书写系统无关。它是 `Named(entity, symbol_id)` 命题的第二个参数。**世界里没有"名字的字符串"这个东西存在的地方。**

#### 5.2.3 音变的运行

```
每 25 世界年（一代），对每个言语社群 g：
    n = Poisson(λ_change · (1 + contact_intensity(g)))        // λ_change ［D 级待标定］
    for i in 1..n:
        c = sample_change(ChangeKind 的先验 × 该语言当前的结构条件, ctr)
        if applicable(c, g.lang):
            g.lang = apply(c, g.lang)                          // 对整个 lexicon 规则地作用
            log SoundChange(c, g, tick)                        // 这是一条真实的因果记录
词汇层（cultural-evolution M9）：
    每概念以 r_replace 概率被本地新形式替换（内部创新）
    以 r_borrow · contact(i,j) · prestige_ratio(j,i) 概率借用邻居形式
类型学层：以 r_typ 概率变化，且**不遵循树**（允许独立的区域扩散）
双言回流（diglossia，M9 对汉语方言链的核心机制）：
    以 p_diglossia ∝ political_integration × prestige(standard) 概率
    把本地形式替换为"标准语"形式，按概念的社会显著性排序
```

**校准锚（`cultural-evolution` M9，均标"已核验"）：**

| 目标 | 数值 | 用法 |
|---|---|---|
| 语言关系的可识别性上限 | **6000–10,000 年**后词汇上不可靠识别（Greenhill et al. 2010） | **硬性验证目标**：模拟中分开 8000 年的两种语言，其同源率必须落到不可辨识水平 |
| 借用容忍度 | 约 **15%/1000 年**的借用率下贝叶斯系统发生仍能恢复接近原树的拓扑（Evans et al. 2021 引述） | `r_borrow` 的"正常接触"量级上界 |
| 类型学演化速率 | ≈ 基本词汇速率，但**更不树状** | 两个子系统必须分开演化，不共用一棵树 |

这三条把 `λ_change`、`r_replace`、`r_borrow`、`r_typ` 从 D 级拉到 B 级——不是给了参数值，是给了**参数必须满足的可观测约束**，可以反解。

#### 5.2.4 两个原始语系的示例配置

**先说一句必须说的话**：手工挑选这两个配置**本身就是一条泄漏通道**。一个 CV 音节 + 声调 + 孤立语的配置读起来"像汉语"，而这正是 F3 §结构指纹要防的东西的类型学版本。规范：**正式主线的原始语言从 `worldgen/phonology` 流按声明的先验采样，不由人手写。** 下面两个配置是**先验的示意抽样**，用于回归测试与文档，明确标记 `illustrative_only = true`，且刻意选成非汉语型（无声调、非孤立、非单音节根）。

```toml
# ─────────── P-Λ（Proto-Lambda）：后缀黏着 + 元音和谐 ───────────
[proto.lambda]
illustrative_only = true
consonants = 12   # 塞音 p t k ʔ / 鼻 m n ŋ / 擦 s ɬ / 流 r / 滑 w j
                  # 特征位表示：无浊塞音系列，有边擦音，有喉塞
vowels     = 3    # 低央 / 高前 / 高后；带长短对立 → 6 个韵核
tone_levels = 0
[proto.lambda.syllable]
onset_min = 0; onset_max = 1
coda_min  = 0; coda_max  = 1
nucleus_complexity = 1
coda_class_mask = "sonorant | +cont,-voice"    # 韵尾只允许 m n ŋ r s
[proto.lambda.phonotax]
sonority_slope_min = 1
ocp_place = true
harmony = { axis = "backness", domain = "word" }   # [±back] 元音和谐
max_word_syll = 5
[proto.lambda.morphology]
strategy = "AGGLUTINATIVE_SUFFIX"
root_shape = "CVCVC"
slots = ["NUM", "CASE", "POSS"]        # 三个后缀槽，NUM 可空
compounding = { productive = true, head = "RIGHT" }
[proto.lambda]
stress = "PENULT"
# 采样出的形式示例（拉丁转写仅为文档展示）：
#   /tavikan/  /murensa/  /ɬopiwar/  /ʔenatuŋ-i-ka/

# ─────────── P-Θ（Proto-Theta）：三辅音根 + 强制韵尾 ───────────
[proto.theta]
illustrative_only = true
consonants = 12   # 浊塞 b d g / 擦 ɸ θ x / 鼻 m n / 流 l / 滑 j w / 小舌 q
vowels     = 3    # 中前 / 低央 / 中后；无长短对立
tone_levels = 0
[proto.theta.syllable]
onset_min = 1; onset_max = 1
coda_min  = 1; coda_max  = 1           # 强制 CVC，无开音节
nucleus_complexity = 1
[proto.theta.phonotax]
sonority_slope_min = 0
ocp_place = true                        # 三辅音根内禁止同部位（跨语言强共性）
harmony = none
max_word_syll = 3
[proto.theta.morphology]
strategy = "TEMPLATIC"
root_shape = "C-C-C"                    # 三辅音根
patterns = 5                            # 五种元音模式承载语法范畴
compounding = { productive = false }
[proto.theta]
stress = "INITIAL"
# 采样出的形式示例：根 /q-θ-m/ 在五个模式下 → /qeθam/ /qaθom/ /qoθem/ /qeθom/ /qaθam/
```

**这两个配置在系统里的用途**：(1) 回归测试音系引擎（给定种子必须产出逐位相同的形式集合）；(2) 音变引擎的黄金测试（P-Λ 经 5 条指定音变后必须得到指定结果）；(3) 演示"两个语系的名字长得不一样，而且不像任何真实语言"。

#### 5.2.5 书写层（`llm-storytelling` F3 第 3 条）

| 层 | 内容 | 谁产出 | 是否存储 |
|---|---|---|---|
| **规范形式** | 音位序列（`PhonemeSpec.id` 的序列） | 音系引擎 | 是（在 `SymbolId` 的原像里） |
| **默认展示** | 一套**固定的、一次性人工选定的**中性拉丁转写表（音位 → 拉丁字母） | 渲染域，纯查表 | 否（现算） |
| **可选展示** | 汉字转写：**固定的音节 → 汉字表**，一次性人工选定语义最中性的字 | 渲染域，纯查表 | 否（现算） |

**硬约束**：
- **不允许模型逐个挑字**（F3 第 3 条原文）。汉字表是 Phase 0 的交付物，是一张静态资产，其哈希进世界线身份。
- 汉字展示层**默认关闭**。理由：即使字表选得再中性，一个用汉字写的国号会被读者读成"这是某朝"，而这正是 F3 §书写层泄漏那一条。开启它需要显式配置，且渲染产物上必须带"此为音译，非世界内文字"的类型标记。
- 世界内**自己**发明的文字系统（`writing-records-memory` M10：不用科技树，用条件 + 低概率触发 + 刺激扩散）是另一回事——那是世界事实（一个 `Structure` 的属性与一套 `Recipe`），与我们的展示层无关。

### 5.3 教义是结构化对象（`llm-storytelling` F3 第 4 条的落地）

采用 `religion-formation-spread` §3.1 的九组字段作为 `ReligionState` 的基底，但按 `spec-world-state` §2.4 的禁令改造：**`Religion` 不是 L0 实体**（该 spec 明确把 `Religion` 列进"回溯性史学建构对象"黑名单）。裁决：

> **`ReligionState` 的每一个字段都必须落在 L0 的 `Proposition` / `InfoCopy` / `Structure` / `RelationEdge` 上；"一个宗教"是观察层 `COMPOSITE_LEXICON` 里的一个检测器输出。**

映射表（本文对两份文件的合并，［本文原创，D 级］）：

| `religion-formation-spread` §3.1 的组 | L0 落点 |
|---|---|
| (1) 超自然主体 `pantheon` | 一组 `Proposition`：`AgentExists(symbol_id, domain_mask, violations_mask)`；四个轴（cosmic_scope / moral_concern / punitiveness / strategic_omniscience）是命题的分档参数，**必须独立，不得合成一个"大神"标量**（该文 §8 反模式 2） |
| (2) 义务与禁忌 `norms` | `ShouldNotTake` / `ShouldDefer` / 新增 `ShouldNotDo(subject, behavior_id, condition_bucket)` |
| (3) 仪式库 `rituals` | `Recipe`（消耗劳动 mh + 物质 g，产出 InfoCopy 强度）+ 三个独立标量（频率 / dysphoria / euphoria）作为 Recipe 系数 |
| (4) 组织形态 `org.form` | **规则侧离散状态机**（该文 §3.3 的七状态与转移条件），LLM 无权调用转移；状态本身住在观察层，转移的物质后果住在 L0 |
| (5) 经济基础 | `holds` 边 + `Structure` + P1/P3 的流 |
| (6) 真理主张 `claims` | `Proposition` + `verifiability` 分档（UNFALSIFIABLE / DELAYED / IMMEDIATE） |
| (7) 内群边界 `boundary.markers` | `SameKindAs` 命题 + 物理标记（`Person` 的不可逆体征 / `Structure` / 食物 `Substance` 的回避） |
| (8) 与政体的关系 | `ShouldDefer` 命题的分布 + P1 胁迫能力 |
| (9) 每聚落传播状态 | `InfoCopy` 的空间分布（这本来就是它） |

**两条硬规范：**

**(a) 每条禁令必须指向真实状态变量。**
```
Norm {
  behavior_id       : BehaviorId        // 必须在 PRIMITIVE_REGISTRY 的 behavior 表里
  direction         : REQUIRE | PROHIBIT
  condition         : [Bucket]          // 激活条件，全部是可计算量
  cost_channel      : ChannelId         // 必须是 §6.3 的 12 条通道之一
  cost_magnitude    : Q32
  detect_by_humans  : Q32
  detect_by_agent   : Q32               // = 该超自然主体的 strategic_omniscience
  sanction_worldly  : [Arg]
  irreversibility   : Q32
}
CI 断言 T-NORM-GROUND:
  ∀ norm: norm.behavior_id ∈ BEHAVIOR_REGISTRY
       ∧ norm.cost_channel ∈ CULTURE_CHANNELS
       ∧ norm.condition 的每个 Bucket 的 axis_id ∈ PRIMITIVE_REGISTRY.substance_axis ∪ field
```
例："禁止在雨季迁徙"= `{behavior_id: MOVE, condition: [Bucket(precip_axis, high)], cost_channel: LABOR_SEASONALITY, ...}`。**指不回状态变量的禁令根本无法被构造**——这不是校验，这是类型。`llm-storytelling` F3 可观察症状第 4 条要求的"无根教义比例"因此恒为 0，指标退化为一个构建期恒真式；真正要监控的变成 `T-NORM-GROUND` 的**豁免申请数**（应为 0）。

**(b) 每个起源神话槽位必须填真实 `event_id`。**
```
OriginClaim {
  slot        : enum { FOUNDING, MIGRATION, ANCESTOR, CALAMITY, COVENANT, REVELATION }
  event_ref   : EventRef | null
  distortion  : [u8; 8]              // 若 event_ref 非空，从真事件到该主张的失真算子链
  reachability: ReachProof           // 见下
}
```
`writing-records-memory` M0 不变量第 1 条："任何 L2/L3/L4 对象上的每一条 proposition，都必须携带一个 `provenance` 链，最终指向某个 L2 记录或某个 agent 的直接经验。**不允许凭空出现的 proposition。**"

本规格把它加强为**可达性证明**：
```
ReachProof = 一条 InfoCopy.source 链，从该社群某成员当前持有的副本
             回溯到一条 Observed(...) 命题，其持有者在事件发生时与事件同格或在信息可达半径内
判据 T-MYTH-REACH:
  ∀ OriginClaim with event_ref != null:  ReachProof 存在且可验证
  ∀ OriginClaim with event_ref == null:  必须标记 pure_fiction = true，
                                          且 pure_fiction 的比例进监控
```
**`pure_fiction` 比例不应为 0**（真实宗教当然有纯虚构的起源神话），但它必须是**规则产生的**（`social-networks-information` M8 的 `ADD_CAUSE` / `ATTRIBUTE_AGENCY` / `MERGE_ACTORS` 算子在传播中生成），不是 LLM 编的。区别是可检验的：规则产生的虚构有 `distortion` 链，LLM 编的没有。

### 5.4 制度是结构化对象

直接采用 `institutional-evolution` M1 的 IG 2.0 编码 + Greif 均衡标注 + 成本模型三层结构，加两条本规格的约束：

1. **`statements` 的语义内容只能从既有 action type / role / entity 词表中选取**（该文 M1"归属"行原文）。LLM 填的是**槽位的引用**，不是文本。
2. **自执行检查是主闸门**（该文 M2）："AI 可以提议制度，但制度能否成立由自执行检查算。" `self_enforcing == false` 的制度**不进入世界状态**，只作为"提出但未成立"的历史事件记录。**`rules_math`；LLM 绝对不能参与这一步的判定**（原文加粗）。
3. **漏洞由语法级枚举生成，不许 LLM 发明**（该文 M10 的七条机械枚举）。LLM 只能"选择用哪个、如何辩护"。
4. **变迁只能是六个离散算子之一**（该文 M11：CREATE / LAYER / CONVERT / DRIFT / DISPLACE / DORMANT），`CREATE` 要求 `ancestry` 非空。
5. **制度死亡只能是五种方式之一**（该文 M20），且**禁止的死亡方式**包括"因为 AI 认为它该结束了"。

`institutional-evolution` M19 已经给出了本领域的完整分工表，本规格全盘采纳，不复述。

### 5.5 LLM 在制度/教义上究竟能做什么

把三份文件的允许清单收敛成一张可执行表：

| 环节 | 归属 | LLM 的输出类型 |
|---|---|---|
| 决定这个聚落是否出现组织化宗教 | 规则（`religion` §3.3 状态机） | 无 |
| 决定新宗教的九组字段初值 | 规则（从结构条件算） | 无 |
| 在规则枚举的 `A(s)` 上给出教义走向的分布（例如"强调洁净 / 强调祖先 / 强调互助"三选一 + NOOP） | **LLM** | `SimplexWeights` |
| 决定该走向的**数值后果** | 规则（§6.3 的 12 条通道） | 无 |
| 给这个宗教、这个神、这条禁令**起名字** | 规则（§5.2 音系引擎） | 无 |
| 把已经确定的结构**口语化成经文文本** | **LLM**（渲染域） | 文本，不回流 |
| 决定制度提案的 IG statement 槽位填哪些既有 role/action | **LLM** | `SimplexWeights` over 规则枚举的槽位填法 |
| 判定该制度是否自执行 | 规则（`institutional` M2） | 无 |
| 生成规避漏洞的候选 | 规则（`institutional` M10） | 无 |
| 决定是否使用某个漏洞 | **LLM** | `SimplexWeights` |
| 为使用漏洞写辩护词 | **LLM**（渲染域） | 文本，不回流 |
| 世内史官如何记载这次变迁 | 规则决定记什么（`social-networks` M12 的 `political_utility` + 覆盖率约束），**LLM 只渲染措辞** | 文本，不回流 |

### 5.6 从 authoring 到 verbalization：这条界线比听上去窄

`llm-storytelling` F3 第 5 条："允许 LLM 参与的唯一文化任务是'措辞'（verbalization），不是'创造'（authoring）。这一区分应当写进纲领第 5 条。——但注意 F10：措辞本身也不是无损的，这条边界比听上去窄。"

**F10 缺失**（说明 0.A），所以"为什么措辞不是无损的"这个论证我读不到。本文给出自己的版本，标 **［本文原创，无来源，D 级］**：

措辞不是无损的，因为**措辞会被人读，而读的人会据此调规则**（`llm-storytelling` F18 也缺失，但 `pseudo-simulation` F2/L4 与 S13 覆盖了同一通道）。一段"很有历史感"的经文会让我们相信这个宗教是合理的，从而降低我们去检查它的结构参数的动机。`pseudo-simulation` S13 的原话："**一个不连贯的世界，只要配一个足够好的世界内史官，看起来就是连贯的**……它让我们**丧失了发现自己内核有病的能力**。"

因此 verbalization 不是"安全区"，而是"**对世界安全、对我们不安全**"的区域。可执行的缓解只有一条，且它是流程性的：

> **验收报告中出现的任何渲染文本，必须并列给出它所渲染的结构对象的完整字段表。** 不允许只给文本。（`pseudo-simulation` S13 第 3 条的推广："任何验收报告里出现世界内史书的引文，都必须并列给出对应的 `world_fact` 差异。"）

### 这一节禁止了什么

- 禁止 LLM 在任何 `name` 字段填自由文本。类型是 `SymbolId`，`Arg` 的定义里没有 `String` variant，因此这不是被拒绝的输入，是不存在的句法位置。
- 禁止 LLM 逐字挑选汉字。汉字转写是一张一次性人工选定的静态表，且默认关闭。
- 禁止把声调、孤立性、音节结构当作我们设定的参数去"选一个像东亚的"；它们从声明的先验采样，声调优先由 `TONOGENESIS` 演化产生。
- 禁止 `Religion` / `Institution` 成为 L0 实体。它们是观察层检测器 + 一堆 `Proposition`/`InfoCopy`/`Structure`。
- 禁止存在指不回状态变量的禁令，禁止存在 `cost_channel` 不在 12 条通道内的禁令。
- 禁止存在既无 `event_ref` 又无 `pure_fiction` 标记的起源神话槽位；禁止 LLM 生成 `pure_fiction`（虚构由传播失真算子产生）。
- 禁止 LLM 参与自执行检查、漏洞枚举、制度死亡判定、宗教组织形态状态机转移。
- 禁止只用渲染文本做验收；文本必须与它所渲染的结构字段表并列出现。

## 6. 文化文本置换不变性检验，与文化能作用的有限数值通道

### 6.1 为什么这是"AI 不决定客观结果"唯一可机械执行的定义

`mandate-contradictions` F3 的论证：第 5 条只禁止了"**直接**决定"，而"直接"这个词在代码里没有对应物。**LLM 生成的文化内容天然带着数值后果**——"这个宗教禁止在春季屠宰耕牛"是一句文本，同时是一个生产函数修改。只要下游有任何一段代码把文本解释成参数（人手写的映射表、或又一次 LLM 调用），AI 就已经在决定客观结果了，而这条通道**不会被"AI 不能写世界状态"这类检查抓住**，因为写状态的是那段解释代码，不是 LLM。

该文给出的二值检验（并自认"完全是我编的"，D 级）：

> 取一条已跑完的历史线，把所有 `CultureObject.labels` 替换成**另一条世界线**的文本（params 一字不改），从 t=0 重放。**世界事实层必须逐位相同。**

**为什么它是唯一可机械执行的定义**：所有其它形式的"AI 不决定客观结果"都需要判断"这个影响算不算直接"，而那是一个语义判断，没有判定程序。置换不变性把整个命题变成一次比特比较：如果文本能被整体替换而世界不变，那么**不存在任何从文本到事实的函数**，无论它藏在哪一层、经过几次转换、由人写还是由模型写。它不需要我们知道通道在哪里，就能证明通道不存在。这是它相对于"代码审查""字段黑名单""架构图"的决定性优势——后三者都要求我们先猜到要找什么。

### 6.2 检验的两个变体，以及为什么必须有两个

**这是本规格对 F3 的实质性修正。** F3 的检验在本项目的架构下**有一个会让它变成恒真式的实现选择**，必须先裁决。

问题：LLM ledger 的键算在什么上？
- 若键算在**渲染后的 prompt 字节**上（`provenance-replay-counterfactual` M5 的写法："`oracle_key = H256(canonical_json(prompt_blocks, model_id, params, tool_defs))`"），则替换名字 ⇒ prompt 变 ⇒ 键变 ⇒ 重放时 cache miss ⇒ 按 M5 的规则**抛错并中止**。检验必然失败，而失败原因与"文本→事实通道"无关。
- 若键算在**结构化 View**上（本规格裁决 L12），则替换名字对键无影响 ⇒ 重放命中同一条响应 ⇒ 同一个 `SimplexWeights` ⇒ 同一个 `a*` ⇒ 世界逐位相同。检验**必然通过**。

**两种实现下这个检验都不 informative。必须承认这一点，而不是把它写进 CI 然后假装它在保护我们。**

裁决与修复：

> **L12：ledger 键算在结构化 View 上**（理由见 §8.2，它同时解决 F4 第三层的蝴蝶效应速率问题）。
> **检验拆成 A、B 两个变体，用途不同，都必须做。**

#### T-SUBST-A（重放变体｜便宜｜每次提交）

```
输入: 历史线 W1（完整 ledger + 每 100 tick 的世界 Merkle 根序列）
      历史线 W2（不同 world_seed）
构造: W1' = W1，但把渲染域的全部产物整体替换为 W2 的对应产物：
        · SymbolId → 拉丁转写表  （整表替换）
        · 汉字转写表              （整表替换）
        · 全部经文/史书/rationale/官方文告的渲染文本（按位置对齐，不足循环填充）
        · 模板文件 template_id → 另一套语义等价模板
执行: 用 W1 的 world_seed 与 ledger，从 t=0 重放
断言: 30 个检查点（每 100 tick）的世界状态 Merkle 根 **逐位相同**
      守恒审计结果相同；事件提名集合相同；因果图边集相同
成本: 一次重放（`computational-feasibility` 的量级：CPU-小时）
```

**它实际能抓什么**（必须写清楚，否则它会被当成万能保险）：
- ✅ 任何 `interpret_doctrine(text) -> Dict[str, float]` 形态的回归。`mandate-contradictions` F3 可观察症状第 3 条："代码里出现 `interpret_doctrine(text) -> Dict[str, float]` 这种函数签名。**看到它就已经中了。**" T-SUBST-A 在这个函数被写出来的那一天就会红。
- ✅ 任何用字符串长度、哈希、字典序参与数值计算的意外（例如按名字排序决定处理顺序 —— 这会同时触发 `spec-world-state` §6.6 的 tiebreaker 违规）。
- ✅ 任何把渲染产物写回 L0 的路径。
- ❌ **抓不到** LLM 中介的文本→事实依赖，因为 ledger 短路了模型。
- ❌ 抓不到"名字影响模型判断"这件事本身。

#### T-SUBST-B（实跑变体｜昂贵｜每次发布）

```
输入: 同一组 world_seed（N = 30），两套符号表 Σ₁、Σ₂（Σ₂ 来自另一条世界线的音系引擎输出）
执行: 每个 seed 在 MODE_FULL 下**真实调用** LLM 各跑一次，共 60 条线，跑 500 年
      （不是 3000 年：这是一个分布检验，短线 × 多种子的功效高于长线 × 少种子）
断言: 在 K = 8 个**预注册**宏观观测量上，Σ₁ 组与 Σ₂ 组的分布不可区分：
        · 双样本能量距离检验（energy distance），α = 0.05，Holm 校正 8 次比较
        · 且效应量必须小于**空分叉噪声地板**（同 seed 同符号表跑两次的差异，
          由 LLM 非确定性产生，见 §8.1）
        · 判据: max_k (effect_size_k / noise_floor_k) < 1.0
```

**预注册的 8 个宏观观测量**（与 `spec-world-state` §8.4 的自主性向量共用，避免两套指标）：政体数、最大政体规模、政治重心位置、城市化率、农牧分界线位置、独立宗教组织数、文字出现时间、语言分化树的不平衡度。

**T-SUBST-B 就是 §7.7 的语言切换检验的一般化**：换名字、换语言、换模板措辞，是同一个实验的三种扰动。它们共用同一套基础设施（60 条短线 × 预注册观测量 × 噪声地板），因此只算一次钱。

**如果 T-SUBST-B 失败**（大概率会）：这**不是**"世界坏了"，而是"名字确实影响了模型的判断"。处置不是修 bug，是：(a) 把该效应量作为一个必须公布的数字；(b) 若效应量超过噪声地板 3 倍，触发 §12 的退路评估。因为它意味着世界事实层依赖于我们随手选的一套音节。

### 6.3 文化能作用的有限数值通道（12 条）

`mandate-contradictions` F3 给出的清单（建议 ≤12 条），本规格全盘采纳并逐条给出可执行定义。

**首先是一处必须解的冲突**：F3 的写法是

```
CultureObject = { params: Vector[float], labels: Text, label_provenance: LLMCallRef }
```

但 `spec-world-state` §2.4 明确禁止 `culture_score` 一类"无微观所指的宏观标量"，且禁止 L0 出现浮点、字符串、以及 `Culture` 这个回溯性建构对象。两者字面冲突。

**裁决（L11）**：

> **这 12 条通道不被存储。它们是从 L0 结构状态 + 该 Actor 可达的 `InfoCopy` 多重集算出的纯函数值，在 `sense`/`propose` 相位现算、按 tick 记忆化、不进快照、不进世界哈希。**

这同时满足两边：F3 要的"参数由规则从结构状态计算，LLM 只读不写"成立；`spec-world-state` 要的"没有 Culture 对象、没有宏观标量字段"也成立。**代价**：每 tick 要为每个活跃 Actor 算 12 个函数（`≤ 2×10⁵ 家户 × 12` 次定点求值，约 2.4×10⁶ 次，相对于该 spec 的 tick 预算可忽略）。

```
CULTURE_CHANNELS : [ChannelSpec; 12]

ChannelSpec {
  id            : ChannelId
  fn            : fn(&StructuralSlice, &InfoMultiset) -> Q32      // 纯函数，定点
  range         : (Q32, Q32)
  reads_fields  : [FieldId]        // 静态声明，CI 校验实际读取集 ⊆ 此集合
  reads_props   : [PropFormId]     // 只读命题的**结构**（谁持有、多少份、多强），不读内容
  consumed_by   : [PrimitiveVerb]  // 哪些机制读它
  evidence      : Grade
  source        : &str
}
```

| # | 通道 | 结构来源 `fn` 的主要自变量 | 被谁消费 | 证据 |
|---|---|---|---|---|
| 1 | `INGROUP_PREFERENCE` 内群偏好强度 | 持有 `SameKindAs(self, ·)` 命题的对象集合大小与副本强度；婚配网络的模块度 | P1 胁迫的目标选择、P3 转移的对手选择 | **B**（`cultural-evolution` M7 族群标记与文化边界的涌现） |
| 2 | `TIME_DISCOUNT` 时间贴现率 | 存量/年消耗比、产出年际变异系数 CV、上一代的死亡率冲击 | 投资类 Recipe 的选择、`WillTransfer` 的期限分档 | **B** |
| 3 | `DEFERENCE` 对权威的服从 | 持有 `ShouldDefer(self, X, ·)` 的副本强度 ÷ 该 Actor 观测到的 X 的胁迫能力 | P1 的抵抗概率、制度 M2 的 `legitimacy_utility` | **B**（`institutional-evolution` M18 合法性多来源存量） |
| 4 | `COORD_COST_DISCOUNT` 协调成本折减 | 共享命题的重叠度、共居/共餐边密度、共同仪式 Recipe 的执行频率 | 集体行动类 Recipe 的劳动系数 | **B**（`collective-action-cooperation`） |

| 8 | `LABOR_SEASONALITY` 劳动季节性约束 | 生效中的 `ShouldNotDo` 禁令按 `Day_d` 分档的覆盖 × 该档的劳动机会成本 | 生产 Recipe 的可用劳动 `Labour_mh` | **B**（`agriculture-carrying-capacity` 农时） |
| 9 | `SAVING_PROPENSITY` 储蓄倾向 | 存量腐损率 `storage_decay`、掠夺风险的观测频率、`WillTransfer` 义务的存量 | 存量 vs 消费的分配 | **B** |
| 10 | `VIOLENCE_THRESHOLD` 暴力正当化阈值 | 持有 `ShouldNotTake(·, self, ·)` 被违反的观测频率、上一代的暴力死亡率 | P1 的 `π` 中 ACT 的权重 | **B**（`war-conflict-logistics`） |

| 12 | `INNOVATION_ACCEPTANCE` 创新接受度 | 近期采纳的新 `Recipe` 的实测收益、声望源的采纳行为、频率依赖偏向的当前状态 | `cultural-evolution` M3 加性 logit 的一项 | **A/B**（该文 M3/M6） |

**三条硬规范：**

1. **`fn` 只读结构，不读内容。** `reads_props` 声明的是 `PropFormId`（命题**形式**），`fn` 能看到的是"持有 `ShouldDefer` 形式命题的副本有多少份、强度多少、持有者在哪"，**不能**看到命题的 args 之外的任何东西，更不存在"文本"。CI: `T-CHANNEL-PURE` —— 用 `spec-world-state` §3.3 的类型抹除机制，把全部 `SymbolId` 与渲染表替换成 σ 置换，12 个 `fn` 的输出必须逐位不变。
2. **`fn` 的实际读取集必须 ⊆ 声明的 `reads_fields ∪ reads_props`。** 由 `spec-world-state` D1-R4（写集静态可判）的读侧对偶实现。
3. **通道数是 12，硬上限。** 加第 13 条 = 内核版本变更 + 世界作废。理由：这是"文化能影响世界的全部途径"的完整枚举，它的价值完全来自它的封闭性。**每加一条，置换不变性检验的保护范围就缩小一点。**

**这 12 条通道与 `p_LLM` 的关系（容易搞混，必须写清）**：通道值 **是 LLM 的输入的一部分**（粗化后进 View），**不是** LLM 的输出。LLM 影响它们的唯一路径是：LLM 的 Intent → Resolve 改变了 L0 结构 → 下一 tick `fn` 算出不同的值。这条路径长、慢、可追踪，且完全经过规则。

### 这一节禁止了什么

- 禁止把 `mandate-contradictions` F3 的置换不变性检验单独放进 CI 然后宣称"AI 不决定客观结果"已被保证。在 ledger 键算在结构 View 上的架构里，重放变体是恒真式；必须同时有实跑变体。
- 禁止 ledger 的键包含渲染后的 prompt 字节（L12）。
- 禁止存储任何文化参数向量、任何 `Culture` / `CultureObject` 对象。12 条通道是纯函数，不进快照、不进世界哈希。
- 禁止第 13 条文化通道。
- 禁止任何 `fn` 读取命题的内容、渲染文本、`SymbolId` 的原像、或任何 composite 标签。
- 禁止 `interpret_*(text) -> 数值` 形态的任何函数签名进入代码库（lint 黑名单 + T-SUBST-A）。
- 禁止在 T-SUBST-B 失败后"修 bug"。失败是一个必须公布的效应量，超过 3 倍噪声地板则触发退路评估。

## 7. 提示词污染

### 7.1 威胁模型

`llm-storytelling` F8："prompt 里的每一个词都是世界的先验。这不是修辞。" 机制证据：Gao et al. 明确把 LLM 偏离人类行为的原因之一归为 **input language**（A）；Durmus et al. 证明**翻译不能可靠地移动模型的文化立场**（A）——**换语言解决不了，但用中文一定会激活中国史区**。

该文列出的六条通道，本节逐条给出堵法：语言即先验 / 词汇即制度 / 地名即历史 / 纪年与时代标签即剧本 / 元层污染 / **研究简报回流**。最后一条是最危险的："项目已有 22 份、总量约 2.7 MB 的真实历史/考古/经济史简报。**只要其中任何一段文本进入运行时 prompt，这个世界就读到了自己的未来。**……有人为了'让 agent 更懂农业'，把 `agriculture-carrying-capacity.md` 的片段塞进 system prompt，**这个人不会觉得自己在破坏项目**。"

### 7.2 View 的粗化函数（Phase 0 交付物，不是实现细节）

`llm-storytelling` F4 第三层："**反事实实验的核心科学性质（干预的传播速度）被一个纯粹的渲染格式决定了，而这个格式多半是某个人随手写的 `f"{x:.1f}"`。** 这是本轮最让我不安的一条，因为它完全不可见。" 该文替代设计第 3 条：**"粗化函数（哪些量分桶、桶多宽）是 Phase 0 的核心交付物之一，不是实现细节——它同时决定了 cache 命中率、反事实的传播速度、以及所有污染指标的样本量。"**

```
VIEW_COARSENING : Map<FieldId, BucketSpec>      // 进 PRIMITIVE_REGISTRY，版本化

BucketSpec ::= LogBins { base: u8, min_exp: i8, max_exp: i8 }     // 存量、人口、距离
             | Quantile { n: u8, ref_dist: DistId }               // 比率、占比
             | Ordinal  { levels: [&str; n] }                     // 有序类别
             | Relative { anchor: AnchorKind, bins: u8 }          // 相对时间/方位
             | Absent                                             // 该字段永不进 View
```

| 字段类 | 分档 | 桶数 | 理由 |
|---|---|---|---|
| 存量（粮、金属、劳动） | `LogBins{base=2}` | ~14 | 决策对存量的敏感性是对数的；`log₂` 桶使"翻倍"成为一档 |
| 人口 | `LogBins{base=2}` | ~20 | 同上 |
| 比率（食物比 E、耕地占比、依附率） | `Quantile{n=5}` | 5 | 五分位；参照分布是**该世界线自身的历史分布**，不是外部的 |
| 距离 | `Relative{anchor=TRAVEL_DAYS, bins=6}` | 6 | "半日 / 一日 / 数日 / 旬 / 月 / 季"——用行程而非公里，同时去掉了绝对尺度 |
| 时间 | `Relative{anchor=LAST_HARVEST\|GENERATION, bins=6}` | 6 | **绝对年份是 `Absent`** |
| 方位 | `Ordinal{8 向}` + 相对本地地形 | 8 | **经纬度是 `Absent`**（`spec-world-state` §8.2 第 3 条） |
| 文化通道值（§6.3） | `Quantile{n=3}` | 3 | 低/中/高。更细的分档没有依据，且会炸掉缓存 |
| 气候距平 | `Ordinal{5 级}` | 5 | 大旱/偏旱/常/偏湿/大涝 |
| 技术 | 已掌握的 `Recipe` 的**能力向量**分档 | — | **禁止时代标签**：不是"你们处于青铜时代晚期"，而是"本地已掌握含锡合金铸造，未掌握块炼铁"（F8 原文） |

**四个后果，每一个都必须被明确接受：**

1. **蝴蝶效应速率成为一个被声明的设计参数。** 桶越粗，微小反事实扰动被舍入抹掉的概率越高，反事实被静默阻尼；桶越细，扰动立刻传播到所有人，反事实立即爆炸且成本 = 全量重跑。F4 要求的必测项：**把粒度作为自变量（1、2、4 位有效数字各一组）画首次分歧点的分布；若三组分布明显不同，就证明了"科学结论是格式的函数"**，必须把粒度选择当成一个需要论证的设计决策。
2. **缓存命中率由它决定。** 见 §9.4。
3. **所有污染指标的样本量由它决定**（同一粗化 View 出现多次才有多个样本估熵）。
4. **它是 ledger 键的一部分**（L12）。

### 7.3 封闭术语注册表（白名单，不是黑名单）

`llm-storytelling` F8 替代设计第 1 条要求"世界内本体论隔离层"。本规格把它实现为**构造性白名单**，因为黑名单只能挡住我们想得到的词。

> **渲染后的 prompt 字节串，其中每一个 token 必须可以归因到下列四个来源之一，否则拒绝发送。**

```
ALLOWED_SOURCES:
  1. TEMPLATE_LITERALS[template_id]     // 版本化模板里的字面量（人写、评审过、冻结）
  2. SYMBOL_TRANSLIT[symbol_id]         // 音系引擎产出的名字的固定转写
  3. BUCKET_LABELS[field_id][bin]       // VIEW_COARSENING 的档名（人写、冻结）
  4. STRUCTURED_DESCRIPTORS[form_id]    // PropForm / Recipe / Verb 的结构性描述（冻结）

渲染器的类型签名保证这一点：
  render(view: &View, tmpl: &Template) -> PromptBytes
  其中 Template 只能由 TEMPLATE_LITERALS 与占位符构成，
  占位符只能被 SYMBOL_TRANSLIT / BUCKET_LABELS / STRUCTURED_DESCRIPTORS 填充。
  ⇒ 不存在一条把任意字符串插进 prompt 的代码路径。
```

**制度只能用"世界内名字 + 结构描述"指称**（F8 原文）：不是「宰相」，而是「`Tavikh`：一个由 X 遴选、从 Y 抽取 Z、其正当性来自 W 的职位」。这句话在上面的类型里是自动的——`STRUCTURED_DESCRIPTORS` 只有结构性谓词，没有制度标签。

**四张冻结表的规模与评审**：`TEMPLATE_LITERALS` 是唯一由人自由撰写的地方，因此它是全部风险的集中点。规范：模板文件走与内核代码同级的评审；模板变更 = `template_id` 变更 = ledger 键变更 = **该世界线的后续调用全部 cache miss**，因此模板在一条历史线内是冻结的。

### 7.4 渲染期 lint（不是模板期）

F8 替代设计第 2 条："**渲染期 lint，不是模板期 lint。** 对最终发出去的 prompt 字节串做黑名单检查……命中即拒绝发送并报错。检查模板没用，因为污染是变量插值进来的。"

```
lint(bytes: &PromptBytes) -> LintResult:
    // L1 白名单校验（§7.3）：token 归因，任何不可归因 token → REJECT
    // L2 黑名单（哈希集，见下）：
    //    - 真实朝代/国号/年号
    //    - 真实制度词（含"天命/科举/封建/郡县/宰相/丞相/礼/德"这一类）
    //    - 现代政治与伦理词（民主/人权/平等/尊严/同理心/民族国家/资本/阶级斗争）
    //    - 真实地名与水名
    //    - 绝对年份（正则：任何 4 位数字 + 年/BC/BCE/CE/公元）
    //    - 时代标签（青铜时代/铁器时代/轴心时代/新石器/封建社会/奴隶社会）
    //    - 元层词（模拟/文明/游戏/剧本/玩家/AI/模型/prompt）
    // L3 研究简报 shingle 检查（见 §7.5）
    // L4 结构检查：不得含经纬度、不得含 tick 绝对值、不得含 entity_id 的十六进制
```

**黑名单必须以哈希形式存储（［本文原创，无来源，D 级］）。** 理由是一个绕不开的循环：黑名单里必须写下真实历史词，而它必须能被运行时读取，于是**黑名单本身就成了一条把真实历史词带进运行时包的通道**——有人会去读它、会在注释里解释它、会把它当作"世界里可能出现的东西"的清单。

```
BLACKLIST: BloomFilter over  H64(salt || normalize(ngram))
  normalize: NFKC + 去空白 + 小写化（拉丁）；中文按字符切
  n ∈ {2, 3, 4}（词级）
  salt: 构建期常量，进 kernel_version_hash
  运行时包里没有任何一个可读的真实历史词。
  明文黑名单只存在于 CI 构建脚本中（该脚本不进运行时依赖闭包）。
```

**处置**：lint 命中 **不是**致命错误，而是 `FallbackCode::LINT_REJECT` → 按 §2.8 从 `π` 采样。理由：致命中止会让一次 bloom 假阳性毁掉一条 3000 年的长跑。但 `lint_reject_rate` 是监控项，**> 10⁻⁴ 即视为模板被污染**，必须查。

### 7.5 `research/` 对运行时物理不可见

F8 替代设计第 4 条 + 可观察症状第 3 条：

> **构建期物理隔离**：`research/` 目录对运行时代码不可见（不同 package、CI 断言、依赖检查）。简报用来写规则，不能用来写 prompt。
> **构建期断言**：`grep` 渲染后的 prompt，命中 `research/briefs/` 里任何长度 ≥ 8 字的连续片段即构建失败。

**三层实现：**

**(a) 依赖隔离（构建期，二值）**
```
T-RESEARCH-INVISIBLE:
  1. research/ 不是任何运行时 crate/package 的成员，也不在任何 include/data 路径里
  2. 运行时二进制的依赖闭包（cargo tree / 打包清单）不含 research 相关条目
  3. 运行时二进制里 strings 扫描：不得命中 research/ 的任何 ≥8 字 shingle（同 (b) 的哈希集）
  4. 运行时进程的文件系统访问白名单不含 research/（沙箱级，兜底）
```

**(b) 渲染后 shingle 检查（运行期，L3 lint）**
```
构建期（CI 内，可读明文）:
  SHINGLES = { H64(salt || s) : s ∈ 全部长度为 8 的字符滑窗，取自 research/**/*.md }
  规模: research/ ≈ 2.7 MB ≈ 2.7×10⁶ 字符 → ≈ 2.7×10⁶ 个 shingle
  Bloom 参数: 目标假阳率 10⁻⁹ → ≈ 30 bit/元素 → ≈ 10 MB
  假阳率核算: 一次 prompt ≈ 3000 字符 ≈ 3000 shingle
              P(单次 prompt 假阳) ≈ 3×10⁻⁶
              全长跑 1.5×10⁵ 次调用 → 期望 0.45 次误拒
              → 可接受（误拒的处置是 π 采样，不是中止）
运行期:
  for s in shingles(prompt_bytes, 8):
      if SHINGLES.contains(H64(salt || s)): return LINT_REJECT(RESEARCH_LEAK)
```
**命中必须报警**（不只是降级）：`research_leak_hit` 是一个独立计数器，**任何非零值都要人来看**，因为它区别于普通 lint 命中——它意味着有人把简报文本弄进了模板或数据文件。

**(c) 治理**：模板评审的检查项第一条是"这段话的来源是什么"。这一条挡的是最可能的现实情形——不是有人复制粘贴，而是有人**读了简报之后，凭记忆写了一段"农业常识"进 system prompt**。shingle 检查抓不到改写过的内容。这条只能靠治理，必须承认。

### 7.6 提示词改写敏感性检验

F8 可观察症状第 1 条：

> **提示词改写敏感性检验（CI 常设）**：同一世界种子，用 3 份语义等价但措辞不同的 prompt 模板跑。比较制度类型分布、宗教结构分布。**若三者有统计显著差异，那么历史是提示词写的，不是世界写的。**

```
协议（与 T-SUBST-B 共用基础设施）:
  模板 T₁ / T₂ / T₃：语义等价、措辞不同、由不同的人撰写、互不参照
  seeds: N = 30，跑 500 年，MODE_FULL
  观测量: §6.2 的 8 个预注册宏观量 + 制度类型分布 + 宗教结构分布（观察层检测器输出）
  检验: 三组间的 Kruskal-Wallis / 能量距离；Holm 校正
  判据: 效应量 / 噪声地板 < 1.0，全部观测量
  额外必报: mean(B)、mean(E)、Δ_act 在三个模板间的差异
           —— 这比宏观量更灵敏，会先动
```

**`mean(Δ_act)` 在模板间的差异是本检验最有信息量的输出**：它直接量化了 `llm-storytelling` F1 那句话——"**基率是提示词措辞的函数，不是世界的函数**"。如果 T₁ 的 `Δ_act = +0.02` 而 T₃ 的 `Δ_act = −0.03`，那么事件基率的一部分是模板作者的个人风格。这个数字必须公布。

### 7.7 语言切换检验

F8 可观察症状第 2 条："把 prompt 全换成英文 + 生造术语，同种子重跑。若制度形态发生实质变化，中文先验在主导。（注意 Durmus 的结论意味着这个检验**只能检出污染，不能作为解药**。）"

```
协议: 同 §7.6，但扰动是 {中文模板, 英文模板, 英文+生造术语模板}
判据: 同 §7.6
处置若失败:
  - 不是"改用英文"（Durmus: 翻译不能可靠移动文化立场）
  - 而是: (a) 公布效应量; (b) 若 > 3× 噪声地板，该决策类的 llm_eligible := false;
          (c) 若多个决策类同时超标，触发 §12 退路评估
```

**三个扰动检验（名字置换 / 模板改写 / 语言切换）的关系**：它们是同一个实验的三个 arm，共用 seeds、共用观测量、共用噪声地板。合并跑：`3 arms × 3 变体 × 30 seeds × 500 年 = 270 条短线`。这是 §7 全部成本。它必须进 `spec-validation` 的算力预算。

### 7.8 元层污染

F8："告诉模型'这是一个文明模拟'，就把 Civilization 系列游戏、汤因比式大历史、'文明兴衰'的整个体裁装了进去。"

规范：**system prompt 里不出现"模拟""文明""历史""世界""游戏""AI""模型"这七个词的任何语言的任何形式**（进 §7.4 的黑名单 L2 元层词类）。模板的框架只能是第二人称的处境描述 + 选项枚举 + 输出格式说明。**不告诉模型它在干什么。**

代价（必须承认）：这会降低模型的任务理解，可能提高 `PARSE_FAIL` 率。必测：元层词开/关两组的 `PARSE_FAIL` 率与 `mean(B)`。如果去元层导致 `PARSE_FAIL` 率不可接受，正确的处置是**改进结构化输出的 schema**（`output_config.format`），不是把体裁信息加回去。

### 这一节禁止了什么

- 禁止模板期 lint 作为唯一防线；lint 必须在最终字节串上做。
- 禁止黑名单以明文形式存在于运行时包（必须是加盐哈希）。
- 禁止 `research/` 出现在任何运行时 crate 的依赖闭包、数据路径或文件系统白名单里。
- 禁止 prompt 出现绝对年份、时代标签、经纬度、真实地名、真实制度词、现代政治伦理词、元层词。
- 禁止用时代标签描述技术；只能用能力向量。
- 禁止把 View 的数值精度当实现细节；`VIEW_COARSENING` 是版本化的注册表条目，改它 = 内核版本变更。
- 禁止在改写敏感性/语言切换检验失败后"换一个更好的模板"来让指标变绿——那是把模板拟合到指标上。
- 禁止把"换英文"当作文化污染的解药（Durmus：翻译不能可靠移动模型的文化立场）。

## 8. 确定性：LLM 不是种子的函数

### 8.1 事实基础

| 事实 | 数字 | 来源 | 等级 |
|---|---|---|---|
| 温度 0 不保证确定性 | 零匹配输出比例：CodeContests **75.76%** / APPS **51.00%** / HumanEval **47.56%**（829 任务） | Ouyang et al., arXiv:2308.02828 | A |
| 根因是推理内核非 batch-invariant | Qwen3-235B-A22B-Instruct-2507 温度 0 同 prompt 采样 **1000 次得 80 个不同 completion**，前 **102** token 完全一致后分叉；启用 batch-invariant kernel 后 1000 次完全一致 | Horace He, Thinking Machines Lab, 2025-09-10 | C（非同行评议博客，单来源） |
| 模型版本静默漂移 | GPT-4 质数判定 2023-03 **84%** → 2023-06 **51%** | Chen, Zaharia & Zou, arXiv:2307.09009 | A |
| 同上，另一独立观测 | 2023-06-25 模型更新后合成调查响应出现实质性均值回归 | Bisbee et al., *Political Analysis* 32(4):401–416 | A |
| 当前 Anthropic 前沿模型**已移除** `temperature`/`top_p`/`top_k`，且**没有** `seed` | 传入返回 400；适用于 Fable 5/5.1、Opus 5/4.8/4.7、Sonnet 5 | 厂商文档（`claude-api` skill 缓存表 2026-06-24 与 `llm-agent-social-simulation` §M5 一致） | B |

**结论（`llm-agent-social-simulation` §9.3 原文）**：**不可能通过"重新调用模型"来重放历史。** 唯一可行的重放机制是把 LLM 输出当作外部熵源持久化。

**推论（本文追加）**：`spec-world-state` 花了一整节（§6）把内核做成跨机器逐位相同，而一次 LLM 调用就能让这个保证在该决策点失效。因此**"世界的确定性"必须被重新定义为"给定 (world_seed, kernel_hash, config_hash, ledger_hash) 四元组的确定性"**，而 `ledger_hash` 是一个不可从其它三者重算的独立输入。这一条要写进世界线身份的定义（§附录 C 与 `spec-causality` 的接口）。

### 8.2 ledger 契约

```
LlmCallRecord {
  // ── 键（内容寻址） ──────────────────────────────────────────
  call_key      : H256   // = H256( canonical_cbor(view_struct)
                         //        || model_id || model_fingerprint
                         //        || canonical(params) || template_id
                         //        || calibration_table_hash
                         //        || coarsening_version )
  // ★ 注意：**不含**渲染后的 prompt 字节，**不含**符号表哈希（裁决 L12）

  // ── 索引 ────────────────────────────────────────────────────
  world_line    : LineageId
  tick          : Tick_y
  site_id       : H128
  class_id      : u16
  call_seq      : u64          // 该世界线内单调，仅用于审计与排序，**不用于寻址**

  // ── 请求侧 ──────────────────────────────────────────────────
  provider          : enum { SELF_HOSTED, HOSTED_API }
  model_id          : &str
  model_fingerprint : H256     // 自托管 = 权重文件 BLAKE3；托管 = API 返回的版本标识
  params            : CanonicalJson
  view_struct_hash  : H256
  rendered_prompt_hash : H256  // ★ 非键字段，仅供审计与 lint 复核
  rendered_prompt_blob : BlobRef  // 可选保留（默认只对 1% 抽样保留，省空间）

  // ── 响应侧 ──────────────────────────────────────────────────
  response_blob     : BlobRef
  weights_raw       : [u16]        // 解析出的 SimplexWeights
  p_final_q32       : [Q32]        // 归一化+校准+ε 混合之后的实际采样分布
  parse_status      : enum { OK, REPAIRED, FALLBACK }
  fallback_cause    : Option<FallbackCode>
  rationale_hash    : H256         // 自由推理段的哈希（正文进渲染域）
  usage             : { input, output, cache_read, cache_write }
  b_bits, e_bits, s_bits : Q32     // §3.1 三个量，落盘（便宜且免得事后重算）

  // ── 世界侧 ──────────────────────────────────────────────────
  rng_stream_id     : u64   // 恒 = 21 (agent/llm_sampling)
  rng_counter       : u256  // (tick, actor_lo, actor_hi, slot<<32|content_hash)
  chosen_index      : u8
  outcome_hash      : H256  // Resolve 输出的哈希，重放校验用
}
```

**三个运行模式与不变量**（沿用 `llm-agent-social-simulation` §9.3，加严）：

| 模式 | 行为 | miss 处置 |
|---|---|---|
| `MODE_FULL` | 真调用；**先写 ledger 再应用**（write-ahead）。进程在两者之间崩溃，重启时按 ledger 补齐 | — |
| `MODE_REPLAY` | `LlmClient` 换成 `LedgerClient`；按 `call_key` 查 | **miss ⇒ 立即 abort，致命错误，不允许"就近匹配"**。miss 意味着规则层或世界状态变了，"这正是我们要检测的东西，而不是要掩盖的东西" |
| `MODE_COUNTERFACTUAL` | 分叉点前走 ledger；分叉点后 `call_key` 未变的继续复用，变了则真调用并写入**新的分支 ledger** | 见 §8.4 |
| `MODE_HEADLESS` | 完全不调用；全部走 `default_policy` | — |

**为什么键不含渲染字节（裁决 L12 的完整理由）：**

| 若键含渲染字节 | 若键只含结构 View |
|---|---|
| 换一套转写表 ⇒ 全量 miss ⇒ `MODE_REPLAY` 中止 ⇒ 名字变成世界线身份的一部分 | 转写表是纯展示，换它不影响世界（这正是 §6 要的） |
| 模板的一个标点改动 ⇒ 全量 miss ⇒ 历史不可重放 | 模板改动 ⇒ `template_id` 变 ⇒ 键变（**故意的**：模板是先验的一部分） |
| 反事实的传播速度由 `f"{x:.1f}"` 决定（F4 第三层） | 传播速度由 `VIEW_COARSENING`（版本化注册表）决定，是被声明的设计参数 |
| `rendered_prompt_hash` 无处安放 | 它作为非键审计字段存在，lint 复核与事后取证仍然可做 |

**代价（必须承认）**：结构 View 相同但渲染字节不同的两次调用会共用一条 ledger 记录，而它们**实际发给模型的东西不一样**。这意味着 `MODE_REPLAY` 复现的是"当时那次调用的响应"，不是"当时那个字节串会得到的响应"。这个区别在换转写表/换渲染器时才显现，而那正是我们希望它不显现的场合。**接受。** 兜底：`rendered_prompt_hash` 不匹配时写一条 `render_drift` 警告（不中止），该计数器进世界线 manifest。

### 8.3 自托管冻结权重 vs 托管 API：按调用是否在因果路径上二分（裁决 L13）

三份文件给出三个不同建议，必须裁决：

| 来源 | 建议 |
|---|---|
| `llm-storytelling` F4 第 4 条 | "**凡是写入世界状态路径的模型，必须本地部署、权重冻结。** 这是昂贵的基础设施决定，它排除了托管的前沿 API。必须在 Phase 0 做——一旦第一条正式历史线用托管 API 跑出来，它就永久失去了可反事实性。" |
| `mandate-contradictions` 决定 8 | "自托管开放权重 + 权重哈希入 ledger + 重放只读 ledger" |
| `computational-feasibility` T4 | 接受用 ledger 重放，但"把 `model_id + weights_hash` 写进世界线身份，并承认：一次模型升级 = 所有旧世界线冻结为只读文物" |
| `llm-agent-social-simulation` §9.2〔R2〕3 | "自托管并不能解救'每 agent 每 tick 一次调用'的架构；它只是把美元换成了 GPU-天。**自托管真正的价值在可复现性**，而不是省钱" |

**裁决：按调用类别二分。**

| 类别 | 定义 | 部署 | 理由 |
|---|---|---|---|
| **Class-1（因果路径）** | 产出 `SimplexWeights`，其采样结果会进 Intent 队列 | **必须自托管、权重冻结**；`model_fingerprint` = 权重文件 BLAKE3，进世界线身份 | F4 层二：反事实的定义就是改变过去，改了过去下游 prompt 就变，ledger miss，必须**重新调用**——而重新调用发生在几周或几个月后。托管 API 上，"移除事件 E 的处理效应"与"模型版本漂移的效应"在同一次实验里完全混淆，且后者效应量未知、无界、不可控 |
| **Class-2（渲染域）** | 经文/史书/官方文告/rationale 的措辞；离线的叙事质量与信息边界审计 | **可用托管 API** | 它的输出永不回流（§11），因此它的非确定性只影响"这次渲染出来的文字长什么样"，不影响任何世界事实。**但产物必须作为带内容哈希的 artifact 落盘，不得静默重生成** |
| **Class-3（离线起草）** | 为规则系统起草候选规则 / 制度 DSL / 假设（`llm-agent-social-simulation` §9.1 允许表末两行；`llm-storytelling` F2 第 3 条） | 任意 | 产物是**确定性代码**，经人审核后固化；生成期非确定性无害 |

**Class-1 自托管的可行性锚**：OASIS 用开放权重 Llama3-8b-instruct + 数十张 A100 跑百万 agent，是"自托管开放权重 + 权重哈希入 ledger"在本领域**已被实践过**的路径（`llm-agent-social-simulation` §6.2）。本项目 Class-1 的调用量是 3×10⁴/线 × 200 线 = 6×10⁶ 次，远小于 OASIS 的量级。

**必须现在做的一件事**：`llm-storytelling` F4 第 4 条的时限是硬的——"一旦第一条正式历史线用托管 API 跑出来，它就永久失去了可反事实性"。因此 **Class-1 的自托管栈必须在第一条 canon 线开跑之前就位**，且必须开启 batch-invariant kernel（Thinking Machines 报告开启后 1000 次输出完全一致，C 级）。这让 Class-1 在实践中接近可重算，虽然我们仍然只依赖 ledger。

### 8.4 反事实默认在 LLM 消融支线上做（裁决 L14）

`llm-storytelling` F4 替代设计第 2 条：

> **双通道，科学结论只走确定性通道。** 每一次 LLM 决策，规则侧必须同时产出一个确定性代理决策（默认策略）。**带因果主张的实验一律在 `surrogate mode`（LLM 通道全关）下运行，世界完全确定。**

`causality-bookkeeping` S5 给出这条规则的代价方向，**必须一起写下来**：反事实时复用 ledger（选项 A）会"系统性低估一切通过人的认知起作用的因果路径"；重新调用（选项 B）会把模型版本差异混进效应量。"因为选项 A 更便宜、更'可复现'，我们一定会默认用它。**于是我们的因果结论会系统性地偏向物质/结构原因，低估决策、信息、误解、人物性格的作用。**"

**规范：**

```
1. 默认: 一切带因果主张的实验在 MODE_HEADLESS 上做。
   MODE_HEADLESS 的世界是完全确定的（内核已经保证，spec-world-state §6），
   于是 Gumbel-max abduction 全程适用，反事实是干净的。

2. 例外: 若因果问题本身就是关于 LLM 决策的（"如果他当时相信了那份情报"），
   才在 MODE_COUNTERFACTUAL 上做，且：
     · 策略固定为 replay-until-divergence（provenance M5 策略 2）
     · 结论强制携带机器可读星号:
         crosses_ledger_region: { n_points: u32, direction: UNDERESTIMATE_COGNITIVE }
     · UI 必须显示"此路径穿过 N 个不可重算决策点，其因果贡献为下界估计"
       （causality-bookkeeping S5 第 2 条）

3. 一次性必做的测量（causality-bookkeeping S5 第 3 条，Phase 1）:
   「通道封闭偏差」实测 —— 对一小批（建议 20 个）事件同时用
     A: 复用 ledger
     B: 固定模型版本、固定采样种子、多次采样求均值 的 fresh 调用
   测两者的效应量差。这个差就是偏差量级。
   若它很大（该红队猜很大），第 5 条与第 2 条的冲突就不是理论问题，
   必须在纲领层面裁决。
```

**空反事实噪声地板是强制前置**（`llm-storytelling` F4 可观察症状第 1 条）：任何反事实结论必须与噪声地板一起报告；**若 `效应量 / 噪声地板 < 3`，该结论无效**。

**LLM 特有的噪声地板**（本文追加，D 级）：在 `MODE_FULL` 下，"同 seed 同配置跑两次"的差异**不为零**（LLM 非确定性）。这是 §6.2 T-SUBST-B 与 §7.6/7.7 全部检验的分母。必须单独测：
```
T-LLM-NOISEFLOOR: N = 30 seeds，每个在 MODE_FULL 下跑两次 500 年（真调用，不用 ledger）
                  对 8 个预注册宏观量，报告成对差异的分布
                  这就是 noise_floor_k
```
**这个数字很可能比人们预期的大**，因为温度 0 下的零匹配比例就有 47.56%–75.76%。若 `noise_floor` 大到让 §6/§7 的全部扰动检验都失去功效，那本身就是一个必须公布的结论：**LLM 通道的方差已经淹没了我们想测的一切信号**，而这是 §12 退路的触发条件之一。

### 8.5 "世界在 LLM 完全关闭时必须能独立跑完三千年"的验证方法

`mandate-contradictions` 决定 8 与 `llm-agent-social-simulation` §9.2 的"设计红线"都提出这条。本规格把它从一条运行时观察升级为**构建期真值 + 每日回归**，共五级：

**(a) 构建期结构保证（二值，每次提交）**
```
T-NOLLM-BUILD:
  以 --no-default-features --features kernel-only 编译，
  LLM crate 在依赖图中**物理不存在**，
  必须编译通过，且全部不变量测试通过。
  ⇒ "世界不依赖 LLM" 成为一个编译事实，不是一个运行观察。
（这是 spec-world-state T-DEPGRAPH 的加强版：T-DEPGRAPH 只要求内核不 import LLM crate；
  本条要求把 LLM crate 整个拿掉之后系统仍然完整。）
```

**(b) 覆盖性断言（二值，每次提交）**
```
T-DEFAULT-COVERAGE:
  ∀ slot ∈ PRIMITIVE_REGISTRY where slot.llm_eligible == true:
      assert slot.default_policy_id != null
      assert DEFAULT_POLICIES[slot.default_policy_id] 是纯函数且不含随机源以外的外部依赖
  ⇒ 不存在"只有 LLM 能做的决策"。
```

**(c) 三千年长跑（每次发布）**
```
T-HEADLESS-3K:
  N ≥ 30 seeds，MODE_HEADLESS，跑满 3000 年
  必过: 无 abort；守恒审计每 tick 精确相等；无实体数触顶；无 clamp 触发率超标
  必报: 灭绝率 P(灭绝)、P(3000 年无 composite polity)、P(永久停滞)
        —— 这三个数按 pseudo-simulation F5 第 5 条是"必须公布的指标"，
           且"一个在 200 个种子上灭绝率恰为 0 的世界是可疑的"
  必报: 8 个预注册宏观量的分布（这是 §4.5 标定协议第 1 步的产物）
```

**(d) 一致性约束（每次发布）**
```
T-POLICY-PRIOR-GAP:
  default_policy(s) 的长期动作分布 与 π(·|s) 的 TVD ≤ 0.05
  理由: 若两者差很多，MODE_HEADLESS 与 MODE_FULL-fallback 就是两个不同的世界，
        §4.3 的孪生线与 §4.4 的预算敏感度会测到一个纯粹由此产生的假信号。
```

**(e) 现象覆盖率（每次发布，本文追加，［原创，D 级］）**
```
T-HEADLESS-REACH:
  对 COMPOSITE_LEXICON 里的每一个 composite（polity / settlement / aristocracy /
  state / dynasty / war / market / scriptural_religion / literacy / ...）:
      r_off = 该 composite 在 30 条 MODE_HEADLESS 线中被检出至少一次的比例
      r_on  = 该 composite 在 30 条 MODE_FULL   线中被检出至少一次的比例
  报警: r_off == 0 且 r_on > 0.5
        ⇒ 该现象只在 LLM 打开时出现 ⇒ 它是 LLM 的产物，不是世界的产物
  处置: 该 composite 的一切结论必须标注 "LLM-dependent"，
        且不得作为"世界演化出了 X"的证据。
```
**(e) 是本节最直接回答"如何防止模型为了戏剧性制造事件"的一条**：它不测事件率、不测比特，它直接问"有没有哪一类历史现象是只有开了 LLM 才会出现的"。这个问题的答案是二值的、不可辩解的、也不能靠调阈值刷分。

### 这一节禁止了什么

- 禁止用"温度 0"或"记录种子"作为 LLM 可重放的手段——前沿模型连这两个参数都没有了。
- 禁止 `MODE_REPLAY` 在 ledger miss 时做"就近匹配""降级模型""重新调用"。miss 是致命错误。
- 禁止 Class-1 调用使用托管 API。第一条 canon 线开跑前自托管栈必须就位，否则该线永久失去可反事实性。
- 禁止 ledger 键包含渲染字节；禁止不记录 `rendered_prompt_hash`。
- 禁止在 `MODE_FULL` 上做带因果主张的实验，除非该因果问题本身关于 LLM 决策，且结论带机器可读星号与方向标注。
- 禁止在没有空反事实噪声地板（含 LLM 噪声地板）的情况下报告任何反事实结论；`效应量/噪声地板 < 3` 的结论无效。
- 禁止存在没有 `default_policy_id` 的 LLM 决策槽位。
- 禁止把"LLM 全关能跑"当作运行时观察；它必须是编译期事实（`T-NOLLM-BUILD`）并每日回归。
- 禁止把只在 LLM-on 出现的 composite 现象当作"世界演化出了 X"的证据。

## 9. 成本与调度

### 9.1 LLM 永不在 tick 关键路径上（裁决 L15），以及与 `spec-world-state` 的一处冲突

`computational-feasibility` F5 替代设计第 1 条：

> **LLM 永远不在 tick 的关键路径上。** `decide` 相位读**上一 tick** 的 View，产出的 Intent 在**下一 tick** 的 `resolve` 里消费。tick 循环永不阻塞在网络上。代价是所有 LLM 决策有 1 tick（1 年）的滞后——对一个年尺度的世界，这是可以接受的，而且它本身就是一个合理的"信息传递延迟"（甚至加强第 4 条的信息边界）。

**冲突**：`spec-world-state` §5.3 的 `PHASE_ORDER_V1` 写的是

```
  3    propose               Perception 缓冲区（仅）        Intent 队列（仅）    规则策略 + LLM（读上一 tick 视图）
  5    material              L0 material 块 + Intent 队列   L0 material 块       整步：生产、搬运、交换、建造、破坏
```

相位 3 写 Intent 队列、相位 5 在**同一 tick** 读 Intent 队列。备注里写了"读上一 tick 视图"，但相位表本身允许**同 tick 消费**——若这样实现，tick 5 就必须等 tick 3 的 LLM 调用返回，LLM 就在关键路径上了。这是一个必须消解的歧义。

**裁决（要求 `spec-world-state` 升版为 `PHASE_ORDER_V2`）：**

```
  3    propose      读 Perception[t-1]           写 IntentQueue[t+1]
  5    material     读 IntentQueue[t]（上一 tick 写的）  写 L0
```

**并且：规则 Intent 与 LLM Intent 走同一延迟**（本文追加，［原创，D 级］）。

**为什么"同一延迟"是必须的、而不是可选的**：如果规则决策是同 tick 生效、LLM 决策是下 tick 生效，那么 LLM-off 孪生线（§4.3）与 LLM-on 主线在**时序结构**上就不同——LLM-off 线的所有反应快一年。于是 `event_rate_ratio` 会测到一个纯粹由调度产生的差异，而它长得和污染一模一样。同理，`budget_sensitivity` 的 β 也会被污染：改配额改变了走 LLM 的决策比例，也就改变了平均反应延迟。**统一延迟把这个混淆从根上消掉，代价是所有决策慢一年——而这一年本来就是"决策到动员"的合理滞后。**

`computational-feasibility` C7 已经点出这条的纲领后果："若 LLM 的 Intent 在下一 tick 才被消费，那么'AI 决定发动战争'实际上是'AI 在 T 年提议，规则在 T+1 年结算'。这在语义上是合理的，但纲领的措辞暗示的是同步决策。需要明确改写。" 本规格的 §1.2 (b)(c) 已经改写。

### 9.2 批处理单位：同一 tick 序号 × 全体种子

`computational-feasibility` F5 替代设计第 2 条：

> **批处理的单位是「同一 tick 序号 × 全体种子」，不是「同一世界的一个 tick」。** 200 条世界线锁步推进，每个 tick 索引把 200 × 10 = 2,000 次调用打成一批。批处理延迟被 200 条线摊薄，**集合反而比单跑更划算**。这是本项目唯一能同时拿到 50% 折扣和可接受墙钟的结构。反事实分叉可以单独成组，只要组内锁步。

```
调度器 (ensemble-lockstep):
  for t in 0..3000:
      for each line L in ensemble:            # 并行，纯 CPU
          run_phases(L, t, phases=[0,1,2])    # env / sense
          sites[L] = enumerate_decision_sites(L, t)      # λ 掷骰
          hot[L]   = select_llm_eligible(sites[L], quota=10)
      batch = ⋃_L { render(view_struct(s)) : s ∈ hot[L] }     # |batch| = N_lines × 10
      submit_batch(batch)                     # 异步；不阻塞
      for each line L:
          run_phases(L, t, phases=[3..9])     # 用 batch[t-1] 的结果填 IntentQueue[t]
      await batch[t-1] if not ready           # 唯一的等待点，且它已经等了一整个 tick
```

**关键性质**：整个 ensemble 的墙钟 ≈ 单条线的墙钟。跑 200 条线和跑 1 条线花的时间一样，因为批处理延迟被摊薄。这直接反驳了 `computational-feasibility` F5 那条"特别恶劣的耦合"（性能问题废掉污染检测）：**在 ensemble-lockstep 下，LLM-on 与 LLM-off 的孪生线是同一个 ensemble 里的两组成员，不是两次串行的长跑。**

**反事实分叉的处理**：分叉出的支线加入 ensemble，只要它们的 tick 索引对齐。§4.3 的 59 个滚动窗口 × 2 支线 = 118 条短线，可以在主 ensemble 之外单独成组锁步。

### 9.3 每条世界线的调用总数硬配额

`computational-feasibility` F5 替代设计第 3 条：

> **每条世界线的 LLM 调用总数是一个写死的配额**（建议 ≤ 3×10⁴，即每 tick ≤ 10 次），超配额直接走规则先验、不排队不降级模型。`llm-storytelling` 已经证明事件密度会跟着调用预算走，所以这个配额同时是**成本控制和污染控制，两者是同一个旋钮**。

```
QUOTA {
  per_line_total  : 30_000        // 硬上限
  per_tick        : 10            // 硬上限
  per_class_share : Map<ClassId, Q32>   // 各决策类的份额，冻结
  per_person_life : 200           // 具名人物一生的调用上限（llm-agent M4，该文自标 D 级）
  in_world_historiography : 0     // ★ 模拟期份额 = 0（mandate-contradictions F6）
}
超配额 ⇒ FallbackCode::BUDGET_EXHAUSTED ⇒ 从 π 采样（§2.8）
⇒ 不排队、不降级模型、不推迟到下一 tick
```

**`in_world_historiography = 0` 是一条独立的硬规则**（`mandate-contradictions` F6 结尾）："LLM 调用预算**按世纪封顶且与模拟年份无关**；世界内史学在模拟期的默认 LLM 预算份额 = **0**。这条不写下来，第 24 行会在 Phase 3 静默吃掉整个预算。" 世界内史学在模拟期是**规则 agent 在命题图上的操作**（§10.4），一次 LLM 调用都不用。

**按世纪封顶且与模拟年份无关**：`per_tick = 10` 恒定，因此每世纪 1000 次，与模拟年份无关。F6 的可观察症状第 1 条（"单个模拟世纪的 LLM 调用量随模拟年份单调上升"）因此在构造上不可能发生。**必测**：把每世纪调用数画出来，必须是水平线（或因 `λ` 触发不足而低于上限，绝不能上升）。

### 9.5 墙钟

`computational-feasibility` F5 的墙钟表（单条线，15 万次调用）：串行 @3s = 125 h；并发 64 = 2.0 h；并发 256 = 0.5 h；逐 tick 阻塞发批 @60s 周转 = 50 h；@5min 周转 = 250 h。

**在 ensemble-lockstep 下重算（这是本规格相对该表的改进）：**

```
ensemble = 200 线 × 10 调用/tick = 2000 调用/批，3000 批（每 tick 一批）
批处理周转 T_batch:
  T_batch = 60 s   ⇒ 3000 × 60 s = 50 小时   （整个 ensemble，不是每条线）
  T_batch = 5 min  ⇒ 3000 × 300 s = 250 小时 = 10.4 天
  T_batch = 30 min ⇒ 62.5 天                   ← 不可接受

对照：不用 batch，用实时 API + 并发
  6×10⁶ 次调用 / 并发 256 × 3 s = 70,312 s = 19.5 小时
  成本 = 分层混合 (c) × 6×10⁶ = $33,120（比 batch 贵 2 倍）
```

**裁决**：
- **主 ensemble 用 Batch，且必须实测 `T_batch`。** 若 `T_batch > 5 min`，改用实时 API + 高并发，多付 2 倍钱换 12 倍墙钟。这是一个必须在 Phase 1 用一次真实批处理测出来的数（不能猜）。
- **扩大 ensemble 是免费的墙钟优化**：N = 1000 条线时每批 10,000 次调用，批数仍是 3000，墙钟不变，科学产出 5 倍。**批处理规模在限额内应当取到最大。** 唯一的约束是 rate limit 与 CPU 侧的并行度。
- **自托管（Class-1）改变这张表**：`llm-agent-social-simulation` §9.2〔R2〕3 给的锚是 OASIS 的 5×A100 / 10⁵ agent / 10 步 / 2 天。我们的 Class-1 量是 6×10⁶ 次调用；用小模型（8B 级）+ 连续批处理，单卡吞吐约 10–50 req/s 量级，8 卡 ⇒ 80–400 req/s ⇒ 6×10⁶ / 200 = 8.3 小时。**自托管在墙钟上优于托管 batch，在成本上是 GPU-天换美元。** 这是 Class-1 必须自托管（§8.3）的一个额外好处，虽然不是它的理由。

### 9.6 缓存工程（决定上表能否成立）

```
前缀渲染顺序: tools → system → messages（官方）。本规格不用 tools，故为 system → messages。
稳定前缀（system，必须逐字节稳定）:
    世界常量 + Actor 的 persona 结构描述 + 该 Actor 的 12 条文化通道分档
    + 生效制度的结构摘要 + 输出 schema 说明
    禁止出现: 时间戳、tick 号、随机 id、未排序 JSON、call_seq、任何浮点格式化
易变后缀（messages）: 当前局势 View + 选项枚举
断言（集成测试常设）: 第二次相同请求的 usage.cache_read_input_tokens > 0
    —— 缓存失效是静默的，只表现为账单变高
```

**一个必须承认的紧张关系**：`llm-storytelling` F8 与 §7 要求 prompt 里的一切都来自封闭注册表并逐字节确定；`llm-agent-social-simulation` §9.2 要求前缀逐字节稳定以命中缓存。**这两条是同向的**——封闭注册表 + 确定性渲染天然给出逐字节稳定的前缀。这是本规格少有的一处"安全性与成本目标一致"的地方。

**缓存与 ledger 键的关系**：ledger 键算在结构 View 上（L12），缓存命中算在渲染字节的前缀上。两者是不同的东西，**不得混用**。特别地：缓存命中不意味着 ledger 命中（模型仍然被调用了），ledger 命中不意味着不产生费用（`MODE_REPLAY` 下根本不调用，费用为 0）。

### 这一节禁止了什么

- 禁止 tick 循环阻塞在网络上。禁止同 tick 消费 LLM 产出的 Intent。
- 禁止规则 Intent 与 LLM Intent 走不同的延迟。
- 禁止以"一个世界的一个 tick"为批处理单位。
- 禁止配额是软约束。超配额不排队、不降级模型、不推迟。
- 禁止世界内史学在模拟期消耗任何 LLM 预算（份额恒 0）。
- 禁止每世纪调用数随模拟年份上升。
- 禁止报告"跑完 3000 年要 $N"而不写明 token 与调用数假设。
- 禁止在 system 前缀里出现时间戳、tick 号、随机 id、未排序 JSON。
- 禁止把缓存命中当作 ledger 命中，或反过来。
