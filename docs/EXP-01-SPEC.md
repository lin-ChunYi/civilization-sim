## 0. 这个切片是什么

**一张 64 格小地图上的采集群体，只做四件事：资源再生与采集、消耗、储存、局部迁移（含分裂与灭绝）。跑 300–1000 年。零 LLM。**

它存在的唯一目的：**把接口和检验先立住，并证明那些检验在错误版本上真的会红。** 不是为了产生一段像样的历史。

### 明确不是前置条件

以下全部**不属于** EXP-01，不得成为它开跑的门槛：

| 不做 | 推迟到 |
|---|---|
| 三张地图、200 个种子、全东亚压力测试 | 有了真实性能数据之后再定 |
| 跨架构逐位一致 | 需要时再做；本切片只要求同机确定性 |
| 完整因果追踪平台（读取集闭包、归因报告、PN/PS、必然性剖面） | 等有值得追溯的机制之后 |
| 自托管 LLM、ledger、`D_KL` 污染指标 | 等 LLM 真的接进来 |
| 涌现认证、模式电池、诱饵世界 | 等有社会结构可言之后 |
| H3 网格、真实地形、扰动基底、合成气候 | 等空间机制超出"邻格"之后 |

## 1. 世界状态与单位

**一切状态是整数。内核不出现浮点。** 定点用千分之一（记作 `_m`）。

### 1.1 单位

| 量 | 单位 | 说明 |
|---|---|---|
| 能量 | kcal，`i64` | 唯一的物质计量 |
| 人 | 整数人 | 群体规模 |
| 时间 | 1 tick = 1 世界年 | 无更细时钟 |
| 比率 | 千分之一（`_m`） | 例：`E_m = 1000` 表示食物比 1.000 |

`NEED_PC = 730_000` kcal/人/年（2000 kcal/日 × 365）。这是全部量级的锚。

### 1.2 地图（静态，创生时冻结）

```
8 × 8 = 64 格，第 3、4 列为 barrier（不可通行）
=> A 区 24 格（列 0–2）、B 区 24 格（列 5–7）、barrier 16 格
=> A 与 B 在物理上不连通。这是为区块隔离检验准备的。
邻接：pointy-top 六邻居（奇偶行错位），越界与 barrier 不算邻居
```

每格静态字段（由 `world_seed` 生成后冻结）：

| 字段 | 生成式 | 含义 |
|---|---|---|
| `cap` | `(60 + h % 81) × NEED_PC` | 存量上限，60–140 人年 |
| `regen` | `cap × (200 + h' % 201) / 1000` | 年再生量，`cap` 的 0.200–0.400 |

每格动态字段：`stock: i64`（当前存量，`0 ≤ stock ≤ cap`）。

### 1.3 群体（band）

| 字段 | 类型 | 含义 |
|---|---|---|
| `id` | `u64` | 血缘派生哈希，见 §3 |
| `cell` | 格号 | 当前所在格 |
| `size` | 整数人 | 规模 |
| `store` | `i64` kcal | 储存 |
| `bacc` / `dacc` | 整数 | 出生/死亡的千分位累加器 |
| `mem[cell] → i64` | 稀疏表 | 记得的各格存量值 |
| `memt[cell] → tick` | 稀疏表 | 该记忆是哪一年的 |

**`mem` 里没有的格子就是 `UNKNOWN`，不是 0，也不是"不存在"。** 决策时必须跳过，不得代入任何默认值。

### 1.4 不存在的东西

内核里**没有** `Polity` / `Settlement` / `Culture` / `Religion` / `Class`，也没有 `legitimacy` / `stability` 这类无微观所指的标量。本切片的规模还不需要它们，所以这一条是免费遵守的——**它不构成任何关于涌现的证据**（见宪法 P1 的修正）。

## 2. 更新顺序

**顺序是规格的一等部分，改它等于改模型。** 版本号 `EXP01_PHASE_ORDER_V1`：

```
1  regen        每格 stock = min(cap, stock + regen)
2a claim        每个 band 独立算索取量（只看进入本相位时的 stock）
2b allot        逐格按比例整数分配（同时结算，见 §4.2）
3  consume      吃：先 harvest 后 store；算出 E_m
4  spoil        store -= store × 0.250
5  demography   由 E_m 决定 b/d，走累加器
6a scout        每个 band 侦察一个随机邻格，记下当年真值
6b migrate      按记忆（可能过时）决定是否搬家
7a extinct      size==0 的群体同时移除，先于任何分裂
7b propose      够大的群体基于同一份占用快照各自提出一个目标空位
7c resolve      同一空位的冲突按 band_id 升序裁决，落败者本 tick 不分裂
7d commit       一次性提交全部获胜的分裂
8  log / snapshot
```

**为什么 2 要拆成 claim 与 allot**：见 §4.2。这是本切片实测出来的一个真实缺陷的修复。

## 3. 实体标识与随机性

### 3.1 标识

```
band_id = splitmix64(splitmix64(parent_id ^ (tick << 20)) ^ index)
初始群体：parent_id = 0xC0FFEE, tick = 0, index = 0..5
```

**禁止任何全局自增计数器。** 这不是风格问题：全局计数器会让"在 A 区抑制一次分裂"改变 B 区所有后续实体的 id，进而改变它们的随机数，于是 B 区的历史整个变掉——而这看起来和真实的路径依赖一模一样。**本切片已实测：把 id 换成全局自增，区块隔离检验 3/3 失败。**

### 3.2 随机性

无状态、按坐标寻址：

```
rng(seed, stream, tick, entity_id, slot) = splitmix64 链式混合
流：1=死亡冲击  2=迁移平局  3=分裂方向  4=侦察目标  9=创生
```

改动任何一个分量只影响那一个抽样点。**禁止全局有状态 PRNG。**

本切片**不使用** Gumbel-max（没有多候选的离散决策需要它）。四份规格里关于 Gumbel 的分歧因此在本切片内不必裁决，见 `EXP-01-CONFLICTS.md` C1。

## 4. 规则（精确形式）

### 4.1 再生

```
stock ← min(cap, stock + regen)
inflow_ledger += 实际增加量
```

### 4.2 采集：同时结算

**第一版写成了顺序结算，实测发现健康内核本身有顺序依赖（逆序遍历后 3/3 不一致）。** 原因：两个群体同格时，先被处理的从全量存量取份额，第二个只能取剩下的。按 `band_id` 排序只让它可复现，没让它与顺序无关——顺序变成了一个隐藏参数。这正是 Kehoe 2016 指出 Sugarscape 二十年不可无歧义重实现的那类原因之一。

修正后的两步：

```
2a  对每个 band（只读进入本相位时的 stock，彼此独立）：
      need  = size × NEED_PC
      room  = max(0, size × NEED_PC × 1.000 − store)
      claim = min( stock × size / (size + 30),  need + room,  stock )
                    └── 采集饱和：30 人时拿走该格 50%

2b  对每个格 c：
      tot = Σ claim
      若 tot ≤ stock:  每个 band 拿到自己的 claim
      否则:            give_i = claim_i × stock / tot（整数除）
                       余数 = stock − Σ give，按 (claim_i × stock mod tot 降序, id 升序) 逐单位派发
      stock ← stock − Σ give
```

整数最大余数法 + `id` 决定平局 ⇒ 结果与遍历顺序无关。**实测：逆序遍历 6/6 一致；改回顺序结算 3/3 不一致。**

### 4.3 消耗与储存

```
avail = harvest + store
eat   = min(size × NEED_PC, avail)
store = avail − eat
E_m   = avail × 1000 / (size × NEED_PC)        ← 食物比
spoil = store × 250 / 1000                      ← 年腐损 0.250
```

储存上限 = 1.000 年口粮（写进 §4.2 的 `room`）。

### 4.4 人口

分段线性，**全部是 D 级，本项目自拟**：

```
b(E) :  E ≤ 0.550 → 0        线性至  E ≥ 1.000 → 0.045
d(E) :  E ≥ 1.000 → 0.032
        0.800 ≤ E < 1.000 → 0.055 线性至 0.032
        E < 0.800 → 0.450 (E=0.350) 线性至 0.055 (E=0.800)
死亡冲击：每 band 每年 0.020 概率，d 额外 +0.100/+0.200/+0.300（等概率）
累加器：bacc += size × b_m；满 1000 出一个人。dacc 同理。
```

**解析均衡 Ê = 0.94；实测末年群体 E 的分布与之一致。**

**必须写下的偏差**：`population-dynamics` 简报里的 A 级结论是 LTP 模型的均衡食物比 **Ê ≈ 0.668**（长期 33% 热量赤字，"均衡人口不是吃饱的人口"）。我的两段线性 b/d 曲线**做不到** 0.668 —— 那需要 LTP 的年龄结构形式。**这是一个已知的、量化的偏差（0.94 vs 0.668），不是一个已解决的问题。** 我没有为了对上这个数去扭曲曲线，因为那会是拿结论倒推参数。

### 4.5 侦察与迁移（信息边界的最小形态）

```
6a  j = 随机一个邻格；mem[j] = stock[j]；memt[j] = 当前 tick
      ⇒ 邻格知识是「不完整 + 过时」的
6b  若 E_m < 1000（任何热量赤字）：
      基准 = stock[自己格] × 1.250
      在 mem 里有记录的邻格中找最大值；UNKNOWN 的跳过
      若找到 > 基准 ⇒ 搬过去，损失 store × 0.150   ← 这一项实际恒为 0，见 §7.2 缺陷 5
```

**为什么门槛是 1.000 而不是 0.900**：一个处在马尔萨斯均衡的群体本来就是饿的，它会去打听邻格。1.250 的增益要求负责防止来回震荡。

**第一版的信息边界写得过强**：`mem` 里只有自己格，邻格永远 `UNKNOWN`，于是群体在物理上无法得知隔壁有什么，迁移永不发生（实测 0 次）。侦察是补上的最小机制。

### 4.6 分裂与灭绝

**第一版把分裂写成了顺序执行**：逐个群体检查空邻格并立即落子，于是后一个群体看到的"空位"已经被前一个占掉了——和 §4.2 采集那处是同一类缺陷。改为提出/裁决/提交三段：

```
7a  extinct：所有 size==0 的群体同时移除（储存计入 out_lost）。
             禁止任何形式的重生。必须先于分裂，否则腾出的空位对本 tick 是否可用取决于遍历顺序。

7b  propose：占用快照 occupied = 此刻全部群体所在格（此后本 tick 内不再变动）
             对每个 size ≥ 40 的群体：
                 free = 它的邻格中不在 occupied 里的
                 若 free 非空，提出一个目标 j = free[rng(seed, S_SPLIT, tick, id, 0) % |free|]
             每个群体最多提一个申请，且只看 occupied，不看别人的申请

7c  resolve：按目标格分组；同一空位有多个申请者时，胜者 = min(band_id)
             落败者本 tick 不分裂，也不改选其它空位（改选会重新引入顺序依赖）

7d  commit： 对每个 (目标格, 胜者) 一次性提交：分出一半人与一半储存，新 id 见 §3.1
```

`min(band_id)` 是一条任意但确定的规则：它不偏向任何空间位置或群体大小，只要求可复现且与顺序无关。

**覆盖率必须如实记录**：长跑（7 种子 × 300 年）里分裂申请 175 次、**撞车 0 次**——7c 这条路径在长跑中从不被执行。因此它由一个定向场景（两个够大的群体唯一的空邻格都是同一个 X）单独覆盖，见 §10 的 T7。**没有那个定向场景，7c 就是一段没有任何测试碰过的代码。**

### 4.7 守恒律

```
Σ stock + Σ store  ==  初始 + inflow − out_eat − out_spoil − out_move − out_lost
```

整数，**必须精确相等**。这是本切片最硬、最便宜的检验。

## 5. 输入 / 输出 / 快照 / 账本

**输入**：一个配置文件，含 `world_seed`、`years`、全部参数、每个参数的 `evidence_level` 与 `source`。参数只能从这里读，不得散落在代码里。

**输出**：
- `yearly.csv`：每年一行 —— 群体数、总人口、总存量、总储存、E 的分位、迁移数、分裂数、灭绝数、守恒误差
- `events.jsonl`：只记离散事件（split / extinct / migrate），带 `tick`、实体 id、前后格号
- `final.json`：末状态全量
- `state_hash`：末状态的 blake2b-128，用于确定性比对

**快照**：全量状态的深拷贝（本切片规模小，不需要结构共享）。要求：**从第 150 年的快照续跑到 300 年，必须与不中断的运行逐位相同。**

**状态比较必须是完整的。** 第一版的 `state_hash` 只覆盖 `cell/size/store/bacc/dacc`，**漏掉了 `mem` 与 `memt`**——而这两个字段直接决定下一次迁移去哪，漏掉它们等于让确定性检验对整整一类 bug 失明（例如一个只污染记忆而不污染当前位置的错误，能安静地通过 T1/T2/T3）。现在的口径：

| 哈希 | 覆盖 |
|---|---|
| `state_hash` | `tick` + 每格 `stock/cap/regen` + 每个群体的 `cell/size/store/bacc/dacc/mem/memt` + 全部 11 个账本计数 |
| `region_hash` | 该区块的格与群体的**同一套完整字段**；不含全局账本计数（它们跨区块累加，本来就会被另一区块的干预改变） |

群体字段集中在 `BAND_FIELDS` 与 `_band_blob()` 一处定义，新增字段时只改这一处。

**运行身份与状态摘要必须分开记录。** `state_hash` 只描述"当前长什么样"，它**不含** `seed`、`start_stock`、`start_store`，因此**单靠它不能识别一次运行**——两次不同的运行在原理上可以撞出同一个 `state_hash` 而我们无从分辨。

| 摘要 | 覆盖 | 回答什么 |
|---|---|---|
| `run_id(st)` | `seed` + `start_stock` + `start_store` + **语义**注入标志 + 全部规则参数与地图形状的指纹 | 这是**哪一次**运行 |
| `state_hash(st)` | 见上表 | 这次运行**当前**是什么状态 |
| `full_digest(st)` | `run_id` / `state_hash` | 对外比较两次运行时应当用的东西 |

**注入标志分两类，且是封闭集合**：`TRAVERSAL_POISONS = {order, revorder}` 只改遍历方式、**不进运行身份**；`SEMANTIC_POISONS = {float, seq, seqsplit, clamp, counter, omniscient}` 改变世界语义、**进运行身份**。把遍历标志误当成语义差异，会让 T6/T7 假失败——那两个检验的全部意义就是"同一次运行换个遍历顺序，结果必须一样"。未登记的标志名在 `make_world()` 处直接报错，不允许静默按非语义处理。

**账本**：只有守恒账本（六个累计量）与事件日志。**没有因果图、没有读取集、没有归因报告。** 因果能力推迟到有值得追溯的机制之后。

| 12345 | 28 | 648 | 278 | 3 | 4.6 年 | 22 | 0 | 22 | 0 | 0 |

### 7.2 已知缺陷与待解释的观察（如实列出，未修）

**观察 1（待解释，不是已确诊的缺陷）—— 默认样本里没有出现灭绝。** 7 个种子、300 年与 1000 年，一次灭绝都没有。

三件事必须分开说：

- 这是**固定配置下的一次观察**，不是"机制错了"的证明。本切片没有任何灭绝兜底：`size == 0` 的群体被无条件移除，重生被明确禁止，所以它不属于宪法 §3.1 禁用清单里的"兜底逻辑"。
- 已知的机械原因有两条：`dacc` 累加器在 `size` 很小时每年攒不满 1 人；任何持续赤字会先触发迁移，群体得以逃走。这两条**解释了样本里为什么没有灭绝**，但不足以判定"在这套规则下灭绝不可能"——后者需要专门的可达性分析（例如构造一个四周皆贫、无处可迁的局面看群体会不会归零），**本轮没做**。
- **与宪法 §5.1 第 2 项的关系**：那一条把"灭绝率恰为 0"写成预注册拒绝条件，语境是"200 个种子的完整世界里出现了兜底逻辑"。本切片的样本量、机制集合与那个语境都不同，且经检查确实不存在兜底，因此这条观察**不触发**该拒绝条件。它保持公开记录，等灭绝通路被专门检验之后再回来判定。

**本轮明确不做**：不新增最低人口清除阈值，不提高死亡率，不为了让灭绝出现而调整任何机制。把一个待解释的观察改造成"预期现象"，才是真正会污染后续判断的动作。

**缺陷 2 —— 饱和是规则几何造成的，不是资源造成的。** 饱和时均 E ≈ 1.7，群体并不饿；限制人口的是"分裂要求相邻有空格"这条规则。也就是说本切片的天花板由 §4.6 的一行条件决定，而不是由承载力决定。**任何关于"这个世界的承载力"的说法在本切片里都是错的。**

**缺陷 3 —— 均 E ≈ 1.6 与解析均衡 0.94 不符。** 因为世界还没被填满，多数群体处在扩张相而非均衡相。300 年不足以让这张地图达到资源约束。

**缺陷 5 —— 迁移的储存损失参数是死的，实际恒为零。** `MOVE_LOSS_M = 0.150` 从未起过作用。原因是结构性的而非偶然：迁移只在 `E < 1.000` 时触发，而 `E < 1` 意味着 `avail < need`，于是 `eat = avail`、`store = avail − eat = 0`——**一个群体只有吃不饱才搬家，而吃不饱时储存必然已经被吃光**。实测：7 个种子 × 300 年里，807 个满足迁移条件的 band-年样本，`store` 全部为 0。

后果：迁移在本切片里**没有成本**。这会高估迁移频率，也让"要不要搬"这个决策失去权衡。修它有两条路——把损失改成作用于人口而不是储存，或者让迁移在 `E` 尚未跌破 1 时就可以发生（那样搬家时手里还有粮）——**两条都会改变世界形态，所以不在本轮动，记录在此，也不带进下一个切片**。

**缺陷 4 —— "事后看错的迁移"只有 1%–3%。** 信息滞后 4–6 年确实存在，但滞后的代价很小，因为格子的存量会朝 `cap` 恢复，所以过时的信息在方向上通常仍然对。**这意味着本切片的信息边界虽然存在，却几乎没有后果。** 要让它有后果，需要资源的波动快于侦察频率（例如年际气候波动）——那超出本切片范围。

## 8. 错误注入

**规则**：每个二值检验配一个错误版本；错误版本必须让目标性质**真的**失败。没触发的**不删除**，而是查清为什么，并写下它在什么条件下才会承重。

| 变体 | 注入什么 | 目标性质 | 实测 | 结论 |
|---|---|---|---|---|
| `poison-counter` | `band_id` 改全局自增 | T3 区块隔离 | 隔离保持 **0/4** | **触发** |
| `poison-seq` | 采集放弃同时结算，回到顺序结算 | T6 逆序不变性 | 顺序不变性保持 **0/4** | **触发** |
| `poison-seqsplit` | 分裂放弃同时提交，回到顺序解决空位（先到先得） | T7 冲突解决与顺序无关 | 正序胜者 P / 逆序胜者 Q | **触发** |
| `poison-omniscient` | 迁移读当年真值而非记忆 | T5 信息边界 | 事后看错 **0/2160**（健康版 30/1947） | **触发** |
| `poison-clamp` | 腐损处加 `max(0, ·)` | T4 守恒审计 | 守恒保持 4/4 | **未触发** |
| `poison-float` | 采集用浮点 | 跨架构逐位一致 | 同机确定性保持 4/4 | **本切片检不出** |

`poison-seqsplit` 挂在 T7（定向场景）而不是 T6（长跑）：长跑里撞车 0 次，挂在 T6 上它永远不会触发——**那会是一个看起来绿、实际什么都没测的测试**。

**两个未触发的，为什么不删：**

- `poison-clamp` 在本切片是**空操作**：`spoil = store × 0.250` 永远不会让 `store` 变负，因为消耗已经被可得量封顶了。它会在"赤字可以把储存打成负数"之后承重——也就是引入借贷、债务或强制征取之后。**保留，标记为在本切片内空转。**
- `poison-float` 的目标性质（跨架构逐位一致）**本切片明确不要求**。同机上 Python 浮点是确定的，所以现有检验抓不到它。**保留，标记为超出本切片范围**；它在要求跨机器复现时才承重。

**注意**：本切片没有 `poison-label`（类型标签污染）——因为内核里根本没有 composite 标签可抹除。等有了才加。

## 11. 必须由你决定的取舍

只有四条。其余我已按上文裁决并同步改了规范。

**已定（本轮审阅裁决，不再是待决）**：
- **目标语言继续用 Python。** 将来换语言时必须重跑全部 11 项必过检验。

- **缺陷 5（迁移损失恒为 0）本轮不修**，且**不带进下一个切片**——下一个切片必须在它被正视之前不依赖"迁移有成本"这个前提。

**待决 3 —— 信息边界要不要在本切片里有后果。** 现在滞后存在但代价只有 1%–3%（缺陷 4）。要让它有后果，最小的做法是给格子的再生量加年际波动，使过时信息真的会误导。这会引入本切片原本排除的"气候"雏形。选项：(a) 保持现状，承认信息边界在这个切片里近乎装饰；(b) 加一个最小的年际波动项。我倾向 **(a)**，把它留到下一个切片，因为 (b) 会让"资源波动"这个大题目从后门进来。

**待决 4 —— 下一个切片往哪走。** 两个方向：(a) 深度——在同一张小地图上加"储存被他人取走"（即最早的胁迫与再分配），这会立刻让 `poison-clamp` 承重并逼出"义务"这个对象；(b) 广度——把地图放大、加年际气候波动，先把资源动力学做扎实。**这两个方向的第一行代码不一样，所以需要你选。**
